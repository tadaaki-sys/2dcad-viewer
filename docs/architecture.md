# フォルダの役割と依存の向き

2D CAD Viewer を本格的な 2D CAD へ段階的に広げるための、フォルダの役割と規則です(Phase 1c で整理)。
規則は自動テスト `src/architecture.test.ts` で確認しています。違反すると `npm test` が失敗します。

## 全体の形

```
画面(React)  App.tsx / components/ / cad-view/
     │
     ▼
app/  アプリの動き(コマンドなど。画面の機能は使わない)
     │
     ▼
io/  ファイル形式の読み書き(DXF・DWG、ワーカーの中の処理)
     │
     ▼
core/  CADの中核(モデル・幾何・選択・スナップ・測定・表示の座標)
     │
     ▼
types/  共通の型(CadEntity など)
```

- **矢印の向き(上から下)にだけ、読み込んでよい**のが原則です。下の層は、上の層を知りません。
- **下の層へは、1つ飛ばしでも直接読み込んでよい**です。たとえば、画面から `core/` を直接使ってかまいません(`CadCanvas` は、選択やスナップを直接使っています)。

## 各フォルダの役割

| フォルダ | 役割 | 読み込んでよいもの | 使ってよい実行環境の機能 |
|---|---|---|---|
| `src/core/` | CAD の中核。画面にも、ファイル形式にも依存しない。 | `core/`、`types/` だけ。外部パッケージは使わない。 | ECMAScript の標準だけ(ブラウザの `window`・`document`・Canvas も、Node の機能も使わない) |
| `src/io/` | ファイル形式の読み書き。DXF・DWG の解析、元データの保持、**ワーカーの中で動く処理**。 | `io/`、`core/`、`types/`、決めたパッケージ(`dxf-parser`、`@mlightcad/libredwg-web`)。画面は読み込まない。 | ECMAScript の標準と、ワーカーで使える機能(`TextDecoder`、`WebAssembly`、`console` など)。DOM(画面)は使わない。 |
| `src/app/` | アプリの動き。コマンド(名前・別名・段階・依頼)など、画面と中核の間で「何をするか」を決める。React や画面の機能は使わない(だから単体テストできる)。 | `app/`、`core/`、`types/` だけ。外部パッケージは使わない。(`io/` は、保存とつなぐ段階で必要になったら、規則の変更として加える) | ECMAScript の標準だけ |
| `src/types/` | 共通の型。**型の宣言だけ**を置く(値・関数・クラスは置かない)。 | `types/` の型だけ(`import type`)。 | － |
| `src/cad-view/`、`src/components/`、`App.tsx`、`src/hooks/`、`src/utils/`、`src/devHooks.ts` | 画面(React と Canvas の描画)。**ワーカーを起動・管理するのも画面の側**(`App.tsx`)。 | すべて。ほかの層からは読み込まれない。 | すべて |

### 例外

- **DWG 変換の WASM:** `io/` は、`node_modules/@mlightcad/libredwg-web/wasm/` のフォルダだけを、相対パスで読み込んでよいです。パッケージが、このファイルを公開範囲(`exports`)に含めていないためです。`node_modules` のほかの場所を相対パスで読み込むことはできません。

### 規則の対象外(テスト用のもの)

次のものは、規則の検査の対象外です(何を読み込んでもよい)。その代わり、**本番のコードから、これらを読み込むことはできません。**

- テスト本体(`*.test.ts`、`*.test.tsx`)
- テスト用の補助(`testHelpers.ts`)
- 回帰テスト(`src/regression/`)、E2E(`e2e/`)

## 検査の方法

文字の検索ではなく、TypeScript 自身を使って検査します。そのため、コメント、文字列、変数名(`document` という名前のCADドキュメントなど)に惑わされません。

- **依存の向き:** 構文解析で、`import`、`export … from`、動的 `import()`、型の `import("…")`、`new URL("…", import.meta.url)` を取り出して調べます。読み込む先を文字列で直接書いていない動的 `import()` は、違反とします。
- **実行環境の機能:** `core/` と `types/` は「ECMAScript の標準の型だけ」で、`io/` は「ECMAScript とワーカーの型だけ」で、型チェックします。使ってはいけない機能(`window`、`document.createElement`、`localStorage`、Canvas など)を使うと、TypeScript が「見つからない」として検出します。

### 変更の内容(`ChangeSet`)の約束事(Phase 3)

- 変更は、**必ず `ChangeSet` として** `DocumentSession.apply()` を通す。図面(`CadDocument`)を直接書き換えない。
- 位置(`index`)は、その変更を適用する直前の、描画順の配列での位置。1つの `ChangeSet` の中の変更は、書かれた順に適用する。
- 削除・置き換えは、その位置にある図形が「同じオブジェクト」であることを確かめる。一致しなければ、何も変えずに失敗する(図面が履歴と食い違ったまま進むことを防ぐ)。
- 新しい図形のID(`n<番号>`)は、`DocumentSession.allocateEntityId()` で払い出す。Undo しても払い出し番号は戻らず、同じIDを別の図形に使い回さない。
- コマンドは `addEntitiesChangeSet`・`removeEntitiesChangeSet`・`replaceEntitiesChangeSet` で変更を作る(位置の計算を間違えないため)。
- 描画順の入れ替え(`move`)は、「from の位置の図形を取り出して、取り出したあとの配列の to の位置に入れる」。最前面・最背面への移動は `moveToFrontChangeSet`・`moveToBackChangeSet` で作る(指定した図形どうしの前後関係は保つ)。
- **保存の Phase への申し送り:**
  - 新しく描いた図形は、DXF の ENTITIES 区画に記録として挿入する。描画順の入れ替えは、記録の位置の入れ替え(取り出して、挿入)として扱う。いまの差分の適用(`io/dxf/patch.ts`)は、置き換えと削除だけなので、挿入を足す必要がある。
  - 新しい図形の色は、レイヤー色を数値にして持っている(取り込んだ図形と同じ扱い)。保存では、レイヤー色の指定(BYLAYER)に戻す。
- **編集系のコマンド(Phase 4以降)の約束:** 展開済みのブロックの図形や、寸法など「読み取り専用」の図形は、編集しない。判断に使う分類(editable / readOnly)は `io/` にあるので、`app/` の層が受け取ってコマンドに渡す(`core/` は `io/` を読み込めないため)。

### 作図(Phase 4)の約束事

- 作図コマンドは、図面を直接変更せず、「図形を追加する」依頼(`addEntities`)を返す。画面の側が `DocumentSession.apply()` を通して適用する。**1つのコマンドで描いた分は、1つの Undo の単位**になる。
- 点を順に指示するコマンド(LINE・PLINE)は、Enter(空)と Esc のどちらでも終了し、描いた分を確定する(`onCancel`)。`U` で1点戻す、`C` で閉じる(3点以上)。作図中の Ctrl+Z は `U` として働く。
- ゴム紐(描いている途中の仮の図形)は、コマンドの段階が返す形式に依存しない折れ線(`PreviewShape`)を、画面が重ねて描くだけ。図面のデータは変えない。
- 描く先は「現在のレイヤー」(レイヤー欄で選ぶ。初期値はレイヤー `0`)。非表示のレイヤーには描かない。新しい図形の色は、そのレイヤーの色。
- 描画順: 新しい図形は常に最前面(末尾)に追加する。`TOFRONT`・`TOBACK` は、この作業で新しく描いた図形(ID が `n<番号>`)だけが対象。取り込んだ図形の順序変更は、編集してよい図形かの分類(io の editable / readOnly)をアプリの層へ渡す仕組みと一緒に、Phase 9 で行う。
- 未保存の保護: 変更があると「未保存の変更あり」と表示し、図面を閉じる・別の図面を開く・ページを閉じる(再読み込み)ときに確認を出す。
  - 確認は、画面の状態ではなく `DocumentSession.isDirty` を直接読んで判断する(作図の途中で「閉じる」を押すと、描きかけの図形を確定してから閉じる依頼が続くため、画面の状態はまだ古い)。
  - 描きかけで、まだドキュメントに入っていない図形(LINE・PLINE で2点以上)も、ページを閉じる前の確認の対象にする(`ActiveCommand.hasPendingChanges`)。
  - 新しい図面を読み込んでいる間は、いまの図面を変更しない(作図コマンドは始まらず、元に戻す・やり直し・描画順は拒否する)。読み込みが終わると、いまの図面と変更は置き換えられるため。
  - 保存の Phase では、保存を始める時点で `saveToken` を控え、成功したら `markSaved(token)` を呼ぶ(保存している間に編集が進んでも、保存できた状態だけを保存済みにするため)。`markSaved` と、履歴の破棄(`reset`)は、購読者に状態の変化を知らせる。

### 円・円弧(Phase 5)の約束事

- **角度の規約:** ラジアン。+X軸から反時計回り(CCW)。ワールドのY軸は上向き。保存する円弧は、常に「始点から終点へ反時計回り」で表す(DXFの ARC と同じ)。角度は `[0, 2π)` にそろえる(`core/geometry/construct.ts`)。
- **CIRCLE:** 中心 → 半径。半径は、点の指示(中心からの距離)か、数値の入力。`D` で、直径の数値入力(半径はその半分)。点を待つ段階が数値だけの入力を受け取るには、段階に `acceptsDistance: true` を宣言する(宣言しない段階では、これまでどおりエラー)。
- **ARC:** 標準は3点(始点 → 通過点 → 終点)。3点が通る向きから、反時計回りの始点・終点に直す(時計回りに指示したら、始点と終点を入れ替える)。`C` で、中心 → 始点(半径が決まる)→ 終点(中心からの方向だけを使う。反時計回り)。
- **作らない円・円弧:** 半径が `MIN_RADIUS`(1e-6)未満か `MAX_RADIUS`(1e9)超、3点が一直線(2辺の間の角の sin が 1e-9 以下)や同じ点を含む、中心・始点・終点で、終点が中心と同じ点・始点と同じ方向(角度の範囲が `1e-9` ラジアン未満、または全周との差が同じ未満)、座標が有限でない点を含む。3点が通る円は、中心を絶対座標へ戻したあとの、中心から各点までの距離と半径の食い違いが、半径の `1e-4` を超えるとき(非常に大きな座標の丸め)も作らない。理由を表示して、同じ段階のまま待つ。
- **ゴム紐:** `PreviewShape` は、折れ線(`polyline`)のほか、円(`circle`)と円弧(`arc`)を持つ。画面は、拡大しても多角形にならないよう、キャンバスの円弧で描く。
- **保存の Phase への申し送り:** 円弧の角度は、ラジアンで持っている。DXF の ARC は、度(DXF の 50・51 の値)で、反時計回り。円(CIRCLE)の色は、ほかの新しい図形と同じく、レイヤー色の数値(保存では BYLAYER へ戻す)。

### ダイナミック入力と数値入力(Phase 6)の約束事

- **単位と表示:** 単位は mm 固定。表示は小数1桁(`formatCoordinate`、`formatDynamicValue`、ステータスバーの `formatMm`)。**内部の値は丸めない**(表示のときだけ丸める)。角度は度(+X方向が0、反時計回り)で、0以上360未満にそろえる。
- **入力の受け口は、コマンドライン1つ。** カーソル付近の表示(`components/DynamicInput.tsx`)は、打っている途中の値を映すだけで、入力欄ではない(マウス操作は通す)。点を待っている間に、フォーカスが入力欄に無くても、数字・`.`・`-` のキーを押すと、入力欄へ移って打ち始める。
- **点の決め方は、`core/commands/dynamicInput.ts`(純粋な関数)。** 段階の種類で、入力できる項目が決まる。
  - `absolute`: 基準点が無い(1点目)。X・Y。
  - `polar`: 基準点がある(2点目以降)。長さ・角度(基準点からの極座標)。
  - `distance`: 数値だけを待つ段階(円の半径・直径)。長さだけ。
  - 打っていない項目は、カーソルの値を使う(長さだけ打って Enter なら、角度はカーソルの向き)。
- **キー操作:** 数値を打って Tab で、その項目の値を確定し、次の項目へ(Shift+Tab で前へ)。Enter で、確定した値と、打っている値から点を作って、`CommandSession.submitPoint()` に渡す(クリック・座標入力と同じ入口)。座標(`1000,500`・`@…`)・キーワード・コマンド名・空の Enter(確定した値が無いとき)は、これまでどおりコマンドへ渡す。Esc は、コマンドの取り消し。
- **基準点:** `ActiveCommand.basePoint` が、段階の基準点(相対座標・極座標・長さ/角度の基準)。段階が宣言する(`PromptBase.basePoint`)。円弧の通過点・終点の段階にも設定した。中心・始点・終点の円弧の終点は、方向だけが意味を持つので、基準を中心にした(相対座標 `@` も、この段階では中心から)。
- **確定した値の寿命:** コマンドの状態が進む(`commandRevision` が変わる: 点の指示、キーワード、終了)たびに捨てる。
- **見えているものと、確定するものを一致させる:** 打っている値と、確定した値を、カーソルの点に当てはめた「実効の点」(`applyTypedValues`)を、ゴム紐(`previewAt`)・クリックでの指示・カーソル付近の表示専用の項目の、すべてで使う。例: 長さ 70 を確定してからクリックすると、クリックした向きに、長さ 70 の点になる(ゴム紐に見えていたとおり)。
- **読み取れない値:** Enter では、理由を表示して同じ段階で待つ(入力欄は、これまでどおり空になる)。Tab では、確定せず、項目も動かさず、打った文字も残す(直せるように。前に確定した値で、誤って確定しないため)。
- **含めていないもの:** Grip 編集中の数値入力(Phase 18)、ORTHO・POLAR などの拘束(Phase 8。ダイナミック入力は、カーソルの点から計算するので、後から組み合わせられる)、ダイナミック入力欄での `U`・`C`・`D` のキーワード入力、ON/OFF の切り替え(常に ON)。

### Snap(Phase 7)の約束事

- **種類(`core/snap/snapTypes.ts`):** 端点・中点・交点・中心・四半円点・垂線・接線・近接・延長(図形への吸着。OSNAP)と、グリッド(格子点への吸着。SNAP)。Snap の計算は `core/snap/` に独立していて、Renderer には実装しない(Renderer は、目印を描くだけ)。
- **優先順位:** 図形への吸着のうち、カーソルに最も近いもの → 無ければ近接 → 無ければグリッド(グリッドには許容距離が無く、いちばん近い格子点)。距離が同じときは、これまでの種類(端点・中点・交点)が、新しい種類に勝つ(これまでの結果を変えないため。`GENERATORS` の並びがその規則)。
- **呼び出し(`findSnapPoint`):** 既存の引数はそのまま。`options.enabledTypes` を指定しないと、これまでどおり(端点・中点・交点。近接は `nearestToleranceWorld` を指定したとき)。指定すると、含まれる種類だけを調べる。`fromPoint`(垂線・接線の基準の点)、`gridSpacing`、`extensionAcquireWorld` も options で渡す。
- **基準の点:** 垂線・接線は、`fromPoint`(作図中の直前の点など。`ActiveCommand.basePoint`、測定では1点目)があるときだけ出る。
- **交点の精度:** 線どうしは線分の交点。円・円弧が絡むもの(線×円・円弧、円・円弧どうし)は、折れ線の近似ではなく、解析的に求める(`core/geometry/curves.ts`)。円弧は、角度の範囲内の交点だけ。楕円・スプラインは、これまでどおり折れ線の近似。
- **中心の探し方:** 円は、カーソル付近の図形から。円弧・楕円は、外接の矩形がカーソルから離れていても中心が近いことがあるため、中心の x 座標で並べた索引(空間索引ごとに1回だけ作る。図面が変わるたびに作り直される)を二分探索し、y でも絞る。取り出した図形は、図面の並びの順にそろえる(同じ距離の候補があるとき、索引の有無で選ばれる候補が変わらないように)。
- **数値の安定性(Codex レビューでの修正):** 線分と円の交点は、判別式ではなく、中心から直線までの距離と、垂線の足の位置で求める(非常に長い線分でも、離れた線を接線と取り違えない・交点を失わない)。円どうしの接する許容は、小さい方の円の半径に合わせる(大きな円の内側の、隙間のある小さな円に、架空の接点を作らない)。格子の表示は、格子の番号が 2^53 以上(正確な整数として数えられない)のときは描かない(ループが終わらなくなるため)。
- **延長:** 線・開いた折れ線の端の線分と、円弧の続き(同じ円)。端点がカーソルから acquire の距離(画面上150px)以内にある図形だけが対象で、端点より先の側だけ(図形そのものの上は、近接)。
- **四半円点:** 円・円弧は 0°・90°・180°・270°(円弧は範囲内のものだけ)。楕円は、長軸・短軸の端点(回転を反映)。
- **設定(`core/snap/snapSettings.ts`):** OSNAP・SNAP・GRID のオン・オフ、種類ごとのオン・オフ、格子の間隔(mm。0.001〜1,000,000)。初期値は、端点・中点・交点・中心・四半円点・近接がオン、垂線・接線・延長がオフ、グリッドの表示・吸着はオフ、間隔は 10 mm。このブラウザの localStorage に保存する(`utils/snapSettingsStorage.ts`。保存できなくても動きは変わらない。読み戻した値は、`normalizeSnapSettings` で検証する)。
- **切り替えの入口:** ステータスバーのボタン(GRID・SNAP・OSNAP・設定)、F7・F9・F3、コマンドライン(`GRID`・`SNAP`・`OSNAP`)は、どれも `toggleSnapSetting` の依頼を、同じ実行(`executeRequest`)で動かす。ボタンと F キーは、実行中のコマンドを終わらせない(コマンドラインから動かすのは、コマンドが動いていないとき)。
- **目印と格子の表示(`cad-view/renderer/snapMarker.ts`):** 種類ごとに形(端点=四角、中点=三角、交点=×、中心=円、四半円点=ひし形、垂線=直角、接線=円と接線、近接=砂時計、延長=点線の十字、グリッド=十字)と名前を描く。格子点は、画面上の間隔が 8px 以上のときだけ描く(吸着は、設定どおり)。
- **含めていないもの:** 一時的な Snap の指定(`END` などの入力、Shift+右クリック)、レイヤーごとの対象指定(Phase 17)、ORTHO・POLAR・OTRACK(Phase 8。ステータスバーのボタンも、そこで足す)。
- **設定を変えたとき:** マウスが動かなくても、いまのカーソル位置で、吸着・目印・ゴム紐・座標表示を作り直す(F3 で OSNAP をオフにしたとき、古い吸着位置のゴム紐が残らないように)。F3・F7・F9 は、キーの繰り返し(押し続け)では切り替えない。
- **性能(19万図形の実図面):** 既定の設定で 1 回あたり 約0.03〜0.1 ms(これまでの 4 種類と同程度)。全種類で 約1 ms。図面を変更したあと、最初の Snap だけ、中心の索引を作るため約30〜40 ms かかる(図面の変更時の、空間索引の再構築 約41 ms と同程度)。

### トラッキング(Phase 8)の約束事

- **カーソルの点を決める段階(`core/tracking/resolveCursor.ts`)。** CadCanvas は、これを呼ぶだけ。順に、(1) 図形への吸着(端点・中点・交点・中心・四半円点・垂線・接線・延長。近接を除く)→ (2) トラッキング(ORTHO・極トラッキング・OTRACK)→ (3) 近接 → (4) グリッド。前の段階で決まれば、あとの段階は調べない。トラッキングが全部オフで取得した点も無ければ、これまでの Snap(`findSnapPoint` 1回)と、完全に同じ結果になる(ランダムなテストで確認)。
- **ORTHO:** 基準点があるとき、カーソルを、基準点からの水平・垂直(縦横の距離の大きい方。同じなら水平)に、常に揃える。図形への吸着(端点など)が見つかれば、そちらが優先(ORTHO の軸の上に無くてもよい)。ORTHO 中は、近接には吸着しない(軸の上の点を優先)。SNAP(グリッド)がオンなら、軸の上で、いちばん近い格子点にする。取得した点(OTRACK)からの補助線と軸が交わる所では、その交点。基準点が無い1点目には、効かない。
- **POLAR(極トラッキング):** 基準点から、角度の刻み(5・10・15・18・22.5・30・45・90°)の方向の半直線に、カーソルが画面上10px以内に近づいたら、その方向に揃える(基準点に近すぎるとき=許容距離以内では、揃えない)。トラッキング間隔(mm)が正なら、基準点からの距離を、その倍数に揃える(0 以下になるときは揃えない)。揃えた角度を、点の近くに表示する。
- **OTRACK:** 吸着点(端点・中点・交点・中心・四半円点)の上に、カーソルを約0.3秒(`OBJECT_TRACKING_DWELL_MS`)とどめると、その点を取得する(最大3点。古いものから消える)。同じ点にもう一度とどめると、取得を解除する。取得した点からは、水平・垂直(POLAR がオンなら角度の刻み。基準点が無くても)の両側へ延びる直線が、補助線になる。2本の補助線(取得した点どうし、極トラッキングの線と取得した点の線、ORTHO の軸と取得した点の線)の両方に近づいたら、その交点に揃える(いちばん近い交点)。取得した点は、コマンドの状態が進んだとき(点の指示・終了など。`trackingResetKey`)、点の指示も測定もしていないとき、OTRACK をオフにしたときに捨てる。
- **取得点の管理(`core/tracking/acquisition.ts`):** とどめ時間の計測・取得・解除・最大数・全部捨てる、をまとめた `ObjectTrackingAcquirer`。時間は、外から渡す `Scheduler`(画面では `window.setTimeout`、テストでは仮想の時計)で計る。同じ点かの判定は、座標の誤差を許す(同じ交点が、別の線分の組から、わずかに違う座標で返されても、同じ点)。取得した点が変わると、再描画して、いまのカーソル位置で作り直す。測定の点を確定するたびにも、捨てる(測定は、コマンドの状態が変わらないため)。画面を閉じるときは、計測だけを止める。
- **トラッキング間隔の下限:** 0(揃えない)か、0.001〜1,000,000 mm。極端に小さい間隔では、距離を間隔で割った値が溢れて、座標が有限でなくなるため(保存された値も、同じ検証。揃えた結果が有限でないときは、揃えない)。補助線の交点には、間隔の丸めを適用しない(適用すると、2本の線から外れる)。
- **補助線の描画:** 補助線は、画面(ビューポート)と交わる区間だけを描く(起点が画面から非常に遠くても、画面にかかる部分が出る)。
- **排他:** ORTHO と POLAR は、同時にオンにできない(片方をオンにすると、もう片方がオフになる。`toggleTracking`)。OTRACK は、どちらとも共存できる。
- **ORTHO・POLAR の基準点:** 垂線・接線と同じ。作図中は `ActiveCommand.basePoint`、測定中は1点目。
- **ダイナミック入力(Phase 6)との関係:** 揃えた点が、そのまま入力の「カーソルの値」になる。長さだけを打って Enter なら、揃えた方向に、その長さの点ができる(直接距離入力)。
- **設定:** `core/tracking/trackingSettings.ts`。ORTHO・POLAR・OTRACK(初期値は、3つともオフ)、角度の刻み(初期値 45°)、トラッキング間隔(初期値 0=なし)。このブラウザの localStorage に保存する(`utils/trackingSettingsStorage.ts`。読み戻した値は `normalizeTrackingSettings` で検証し、ORTHO と POLAR が両方オンなら ORTHO だけ残す)。
- **切り替えの入口:** ステータスバーのボタン(仕様の順: GRID・SNAP・ORTHO・POLAR・OSNAP・OTRACK)、F8=ORTHO・F10=POLAR・F11=OTRACK(キーの繰り返しでは切り替えない。F11 は、ブラウザの全画面の切り替えと重なる環境がある)、コマンド `ORTHO`・`POLAR`・`OTRACK`。どれも `toggleTrackingSetting` の依頼を、同じ実行(`executeRequest`)で動かす。ボタンと F キーは、実行中のコマンドを終わらせない。
- **描画(`cad-view/renderer/trackingRender.ts`):** 補助線は、水色の破線で、画面の端まで延ばす(ORTHO だけのときは、描かない)。取得した点は「＋」。極トラッキングで揃えたときは、角度を点の近くに出す。
- **含めていないもの:** Shift キーを押している間だけの一時的な ORTHO、任意の角度の追加、直前の線分からの相対角度での極トラッキング、一時的な Snap の指定(`END` など)、Grip 編集中のトラッキング(Phase 18)。
- **Snap の修正(Phase 8 の確認中に見つけた):** 楕円・スプラインは折れ線に近似していて、その頂点(隣り合う線分が接する点)が「交点」として吸着していた。同じ図形の、隣り合う線分(続けて並んでいる、または、閉じた図形の最初と最後)が、共有する頂点で接しているだけのものは、交点として扱わない(本当の交点、隣り合わない線分が同じ点で交わる点=折れ線が自分自身と交わる点は、これまでどおり)。

ツールバーのボタン、ショートカット(F・M)、コマンドライン、図面のクリックは、どれも `CommandSession` という1つの入口からコマンドを動かします。

### 図形の編集(Phase 9)の約束事

対象は、移動(MOVE・MO)・コピー(COPY・CO・CP)・回転(ROTATE・RO)・削除(DELETE・E・DEL。Delete キー)。1回の操作は、1つの変更(`ChangeSet`)にして `DocumentSession` に渡すので、何個の図形を動かしても、履歴は1段階(Undo は1回)。

- **編集してよいかの判断(`app/document/editability.ts`):** 新しく描いた図形(ID が `n<番号>`)は、常に編集できる。取り込んだ図形は、最上位の図形だけ編集できる。ブロック(INSERT)の中身・寸法は、読み取り専用(`origin.nested = 1`)。元データとの対応づけに失敗した図面(`recordOfParserEntity === null`)は、取り込んだ図形を編集できない。`io/` の分類は、画面の側(`App.tsx` の `editabilitySourceOf`)が `EditabilitySource` に直して渡す(`app/` は `io/` を読めないため)。図面の読み込み中は、編集コマンドを始められない。
- **選択の扱い(`selection` ステップ):** 先に選択してあれば、それを使う。無ければ「図形を選択してから、Enter」と促し、普通のクリック・ボックス選択で選ばせて、Enter で確定する(コマンドラインへの文字入力は、選択ステップでは受け付けない)。編集できない図形が混ざっていたら、編集できるものだけを対象にして、除いた数と理由をコマンドラインに出す。1個も編集できなければ、コマンドは始まらず、理由を出す。
- **移動・回転の適用(`app/document/editing.ts`):** 図形を、剛体変換(移動・回転。`core/geometry/transform.ts` の `Affine2D`)で動かした新しい図形に置き換える(`replaceEntitiesChangeSet`)。ID・レイヤー・色・描画順は変わらない。形以外の属性(ポリラインの頂点の bulge など)は、そのまま。移動量が0・回転角が0度は、何もせず理由を出す。剛体でない行列は、Phase 10 で、相似変換(拡大縮小・鏡像)まで広げた(下の「形を変える編集」)。
- **コピー:** 繰り返して複写する(位置を指示するたびに、1つ複写。Enter・Esc で終了。`U` で直前の複写を取り消す)。終了時に、全部を1つの変更として確定する(Esc でも、それまでの分は確定。途中でコマンドが終わったときも)。複写は新しい図形(`n<番号>`)で、描画順の末尾に、もとの前後関係を保って加える。
- **回転:** 基点 → 角度。角度は、数値入力(度)、または、点の指示(基点からの角度)。ダイナミック入力は「角度」の欄だけを出す(`DynamicMode = "angle"`)。数値入力は、点の入力ステップの `numberMeaning: "angle"` で、長さではなく角度として読む。
- **ゴム紐(`core/commands/entityPreview.ts`):** 選択した図形の移動後の形を、白い破線で出す。図形が多い(300個超)ときは、全体を囲む長方形だけを出す(性能のため)。
- **元データとの対応(`sourceRecord`。保存の Phase への申し送り):** 取り込んだ図形のポリラインは、膨らみ(bulge)を展開した点列に、スプラインは、折れ線に変換されている。保存のときは、この展開後の座標を元の記録に書き戻せないので、「元の記録のID」と「取り込み時から、いま(編集後)までの剛体変換の行列」を、図形に持たせる(`CadEntity.sourceRecord = { id, matrix }`)。移動・回転のたびに、行列を合成する(`composeAffine`)。保存の Phase では、元の記録の座標に、この行列を適用して書く(bulge は、剛体変換で変わらない)。取り込んだ図形の複写も、元の記録への対応(単位行列から)を持つ(保存のとき、元の記録の属性を引き継いで、新しい記録を作る)。新しく描いた図形は、元の記録が無いので、持たない。Undo・Redo は、図形そのもの(`sourceRecord` を含む)を戻す。
- **描画順(TOFRONT・TOBACK)の拡張:** 取り込んだ最上位の図形にも、効くようにした(Phase 4 では、新しく描いた図形だけ)。ブロックの中身・寸法は、これまでどおり対象外(理由を出す)。
- **Delete キー:** コマンドが動いておらず、選択があり、入力欄で文字を打っていないときだけ、`DELETE` を動かす。
- **変更の適用の高速化(`core/history/apply.ts`):** 削除だけ(位置が大きい順)・追加だけ(位置が小さい順)の変更(多数の図形の削除と、その Undo)は、1回の走査で適用する。1件ごとに配列を詰め直す方式では、19万図形の実図面で、散らばった10万個の削除が約34秒かかった(Phase 9 の測定で判明)。条件に合わない変更は、これまでどおり1件ずつ適用する(エラーの文言も同じ)。両者が同じ結果になることを、ランダムな変更のテスト(`applyBulk.test.ts`)で確かめている。
- **性能(実図面。`src/regression/edit.perf.regression.test.ts`。時間は参考値で、失敗にしない):** 10万個の図形の移動 約0.6秒・Undo 約0.1秒・削除 約0.3秒(19万図形の実図面)。1,000個の移動は 約0.1秒。選択のゴム紐は、300個を超えると外形だけなので、図形数によらず約25ms 以下。
- **桁あふれの拒否と安全側の判断(Codex レビューでの修正):** 有限な座標が、変換で有限でなくなる(例: `1e308` の図形を `1e308` 動かす)ときは、変換そのもの(と、`sourceRecord` の合成結果が有限でないとき)を拒否する(1つでも失敗したら、全体を何もせずに拒否。COPY は、全部の形ができてから ID を払い出す)。もともと有限でない座標(壊れたデータ)は、これまでどおり、そのまま扱う。編集可否の分類が、図形の添字と食い違う(範囲外・0/1 以外の値)ときは、編集できる側ではなく、編集できない側に倒す。90°の倍数の判定は、小さい角度(|角度| < 1000 ラジアン)に限り、回転角(度)は 360 で割った余りにしてから使う(巨大な角度でも、精度を保つ)。COPY のゴム紐は、指示済みのコピーの形を、段階ごとに1回だけ作る。
- **回転角の許容:** 90° の倍数から 1e-12 ラジアン(約 6e-11 度)以内の角度は、ぴったりの値にそろえる(座標に誤差を入れないため)。そのため、これより小さい角度の回転は、「回転なし」として拒否される。
- **含めていないもの:** ROTATE の「参照」・「コピー」オプション、COPY の「配列」・「変位」、Grip 編集(Phase 18)、保存(Phase 21・22。編集は、まだファイルに保存されない)。
### 形を変える編集(Phase 10)の約束事: MIRROR・SCALE・STRETCH

エイリアスは MI・SC・S。1回の操作は、Phase 9 と同じく、1つの変更(`ChangeSet`)で、Undo は1回。ブロックの中身・寸法は読み取り専用(除いて、理由を出す)。

- **相似変換(`core/geometry/transform.ts`):** 変換を「剛体(移動・回転)」から「相似変換(移動・回転・一様な拡大縮小・鏡像)」に広げた(`isSimilarity`)。非一様な拡大縮小・せん断・つぶれる変換・非有限な行列は、拒否する。移動・回転だけの変換の計算は、これまでと完全に同じ(別の経路 `transformSimilar` は、倍率や鏡像を含むときだけ通る)。`scaleMatrix(基点, 倍率)`、`reflectionMatrix(軸の2点)`(水平・垂直・45度の軸では、成分がぴったりの値)。
- **図形ごとの扱い(相似変換):** 円・円弧・楕円の半径と、文字の高さには倍率を掛ける。線の太さ・破線の間隔は、変えない。円弧は、鏡像で向きが逆になるので、始点と終点を入れ替える(反時計回りのまま)。楕円の鏡像は、共役な半径から標準形に直す(`ellipseTransform.ts` を再利用)。**文字は、鏡像でも反転させない**(挿入点だけを動かし、向きは変えない)。倍率だけの変換は、角度の値に触らない。桁あふれ(有限な値が有限でなくなる)は、Phase 9 と同じく、全体を拒否する。
- **MIRROR:** 選択 → 軸の2点 →「元の図形を削除しますか? [はい(Y)/いいえ(N)] <N>」(文字で答える。Enter = いいえ)。いいえ=鏡像の複写(新しい図形。`copyEntities`)。はい=元の図形を、鏡像に置き換え(ID・描画順は保つ。`transformEntities`)。軸の2点が同じ点なら、拒否。
- **SCALE:** 選択 → 基点 → 倍率(数値)。`R` で「参照の長さ(数値、または2点)→ 新しい長さ(数値、または、基点からの距離をクリック)」。倍率 = 新しい長さ ÷ 参照の長さ。倍率は、0 より大きく、`1e-6` 以上 `1e6` 以下(1 は何も変わらないので、拒否)。倍率の段階では、クリックは受け付けない(数値で入力する。mm の座標がそのまま倍率になるのを避けるため)。倍率・参照の長さの段階は、`numberMeaning: "plain"`(ダイナミック入力は出さず、コマンドラインで入力)。新しい長さの段階は、ゴム紐が、カーソルまでの距離に追従する。
- **STRETCH:** 交差窓の2点 → 基点 → 移動先。選択は使わない。窓にかかる図形(範囲が窓と重なる、編集できる図形)を、全図形から探す(`AppEditing.findInWindow`。10万図形でも 約20〜35ms)。図形ごとの扱いは `core/geometry/stretch.ts`: 直線=窓の中の端点だけ動く、折れ線・スプライン=窓の中の頂点だけ動く(全部なら、図形ごと移動)、円・点・文字=中心(挿入点)が窓の中なら図形ごと移動、円弧・楕円=全体が窓の中のときだけ図形ごと移動(一部だけ入っているものは対象外で、数を知らせる)。窓の辺の上は、中。ゴム紐は、動かした後の形(候補が 300 個を超えると、移動した窓の枠だけ)。
- **元データとの対応(保存の Phase への申し送り):**
  - `sourceRecord.matrix` は、相似変換(倍率・鏡像を含む)になりうる。保存の Phase は、図形の種類ごとに、元の記録へ適用する規則を持つこと: 円弧は、鏡像で始点・終点の角度を入れ替える。ポリラインの bulge は、鏡像で符号を反転する(拡大縮小では、bulge は変わらない)。円・円弧・楕円は半径に倍率を掛ける。文字は、高さに倍率を掛け、**鏡像では反転させない**(挿入点だけを変換)。
  - **STRETCH で頂点が個別に動いた図形は、行列では表せない。** 取り込んだ折れ線は、円弧の膨らみ(bulge)が展開済みの点列なので、頂点を動かした結果は、元の記録の頂点と対応しない。そのため `SourceRecord.reshaped: true` の印を付ける。保存では、印のある図形を、matrix を適用するのではなく、**いまの形で元の記録を置き換えて書く**(折れ線は、展開後の点列になる。見た目は同じ)。印は、あとで移動・コピーしても、引き継がれる(matrix は合成される)。図形ごと動いた(窓に全体が入った)図形には、付けない(平行移動の行列の合成だけ)。
- **Codex レビューでの修正:** (1) 移動・回転だけの経路に入るのは、倍率が 1 から 1e-12 以内の変換だけ(利用者が指定した 1.0000000001 などは、位置と大きさの両方に倍率を掛ける)。(2) 負の一様倍率(a = d < 0)は 180 度の回転を含むので、角度を更新する。(3) 鏡像軸は、大きい方の成分で割ってから計算する(軸の長さの二乗の桁あふれ・桁落ちを避ける。差が桁あふれするときは null)。(4) STRETCH の円弧・楕円の「全体が窓の中」は、楕円は厳密な範囲(端点と範囲内の極値。`ellipseExactBounds`)で判定する(点列の近似に余裕を足した範囲だと、窓がぴったり囲む楕円まで、一部だけ入っているとみなしてしまう)。境界は 1e-9 の相対許容。(5) ゴム紐は、図形の数(300)に加えて、頂点の合計(`PREVIEW_VERTEX_LIMIT` = 20,000)でも、枠だけの表示に切り替える(巨大な折れ線1本でも、カーソルを動かすたびに全頂点を計算しない。Phase 9 の MOVE・COPY・ROTATE にも効く)。(6) SCALE の参照の長さを2点で指示するとき、距離が桁あふれする点は拒否する。
- **含めていないもの:** 非一様な拡大縮小・せん断、SCALE の「コピー」、MIRROR の文字の反転の選択(MIRRTEXT)、STRETCH での円・円弧・楕円の部分変形、選択済みの図形を使った STRETCH、Grip 編集(Phase 18)、保存(Phase 21・22)。
### トリム・延長(Phase 11)の約束事: TRIM・EXTEND

エイリアスは TR・EX。流れ: 境界の図形を選ぶ(Enter。**何も選ばずに Enter = 表示中のすべての図形**。選択済みのまま Enter なら、その選択が境界)→ 図形をクリック → 続けて何回でも(Enter・Esc で終了)。クリック1回ごとに図面へ反映する(次のクリックは、反映後の形が相手になるため)。**Undo は、1クリックにつき1段階**。

- **クリックは、吸着しない(`rawPoints`):** 点を待つ段階の `rawPoints: true` で、CadCanvas は、吸着・トラッキング・ダイナミック入力を使わず、クリックの位置をそのまま渡す(`CadCanvas` の `pointPickRaw`)。吸着すると、境界との交点に吸い寄せられて、どちら側を切るか決まらないため。クリックと一緒に、図形を指す許容距離(画面6px を図面上の長さにしたもの)も渡す(`onPointPick` の第2引数。App が `pickToleranceRef` に持つ)。
- **対象にできる図形:** 線・円弧・円・折れ線。楕円・スプライン・文字・点は、理由つきで断る。読み取り専用の図形(ブロックの中身・寸法)は、対象にできないが、**境界にはできる**。非表示のレイヤーの図形は、対象にも境界にもしない。クリックの位置に、読み取り専用の図形と編集できる図形が重なっているときは、編集できる方を対象にする。
- **境界にできる図形:** 線・円・円弧・折れ線・楕円・スプライン。円・円弧は、正確に(解析的に)交点を求める。折れ線・楕円・スプラインは、線分の連なりとして求める(楕円・スプラインは近似なので、交点の位置が、近似の細かさの分だけずれうる)。対象の図形自身は、境界にしない。
- **幾何(`core/geometry/trim.ts`):** 対象を「道」として、道に沿った位置 s(線分の連なり=何番目の線分 + その中の位置、円弧・円=始点からの角度)で表す。境界との交点を s で求め、クリックの位置の前後の交点の間を切り取る(`trimKeepIntervals`)。交点の座標は、**位置 s から計算し直さず、そのまま使う**(計算し直すと、30 が 30.000000000000004 になる。水平・垂直の線は、その座標をぴったり使うので、水平・垂直の線を水平・垂直の境界で切る、ふつうの場面で、座標がぴったりになる)。
- **トリムの結果:** 線・折れ線=境界で短くなる。境界が両側にあれば、間が切り取られて、2つの図形に分かれる。円弧=同じ(角度で)。円=交点が2つ以上のとき、クリックした側を除いた円弧になる(**図形の種類が、円から円弧に変わる**。ID は保つ)。閉じた折れ線=交点が2つ以上のとき、クリックした側を除いた、1本の開いた折れ線になる(頂点は、元の順で、巻き込んで)。片側にしか交点が無いときは、そちら側を端まで切り取る。切り取る部分が図形の全体のときは、図形を削除する。交点が無いときは、理由を出して、何も変えない。
- **延長の結果:** クリックに近い方の端を、端の向きのまま(線・折れ線の端の線分。円弧は、円に沿って)、最も近い境界まで延ばす。境界は、延ばさない(境界の実際の範囲に届かなければ、境界ではない)。**端がすでに境界の上にあるときは、その境界を飛ばして、その先の次の境界まで延ばす**(先に境界が無ければ、延長できない)。延ばした先に境界が無い、円・閉じた折れ線も、延長できない(理由を出す)。どちらの端を延ばすかは、クリックに近い方(円弧は、角度で、真ん中より近い端。円弧の外をクリックしたときは、近い端。折れ線は、道に沿った長さで、真ん中より近い端)。
- **反映(`app/document/trimming.ts`):** 1クリック = 1つの変更。1つ残る=置き換え。2つに分かれる=置き換え + 追加(2つ目は新しい図形で、元の図形のすぐ上の描画順)。無くなる=削除。座標が有限でない結果は、拒否する。
- **元データとの対応(保存の Phase への申し送り):** 形が変わるので、`reshaped: true`(Phase 10)を付ける。**切り取りで2つに分かれたとき、2つとも、同じ元の記録を指す**(`sourceRecord.id` が同じ)。保存では、「`id` が元の記録のIDと同じ図形」が、元の記録を置き換え、それ以外(同じ記録を指す、IDの違う図形)は、元の記録の属性(レイヤー・色・線種など)を引き継ぐ**新しい記録**として追加する(コピーと同じ規則)。円→円弧のときは、元の円の記録を、円弧の記録に置き換える。取り込んだ折れ線は、円弧の膨らみが展開済みの点列なので、結果も点列の折れ線(見た目は同じ)。
- **性能(実図面、1クリック):** 19万図形で 平均 約130ms・最大 約215ms(全図形の範囲の計算が中心。範囲が重なる図形だけを、境界として調べる)。10万図形で 平均 約80ms。1万〜2万図形では 約15ms。
- **Codex レビューでの修正:** (1) 円弧の延長で、円弧の中をクリックしたとき、遠い方の端を延ばしていたのを直した。(2) 折れ線の延長の端を、線分の数ではなく、道に沿った長さで選ぶ。(3) 位置 s(割合)の許容を 1e-12(割合の丸め誤差より十分大きく、長い線でも実際の長さが大きくならない値)に絞り、座標(mm。境界の端の判定)の許容 1e-9 と分けた(割合が 1e-9 だと、長さ 1e12 の線で 1000 に相当し、残すべき短い区間を消していた)。(4) 境界の範囲の絞り込みに、1e-6 mm の余裕を持たせた(core は境界の端から 1e-9 mm 外れた交点も認めるので、丸め誤差でわずかに離れた T字の接点を、前段で捨てない)。(5) 折れ線の頂点の引き継ぎを、座標で全頂点を探す方式(最悪、二乗)から、頂点の図形そのまま渡す方式に変えた(10万頂点の折れ線でも 速い)。(6) 測定モード中でも、TRIM・EXTEND のクリックは、吸着しない(コマンドが、測定より先にクリックを受け取るため)。
- **見送った指摘:** 円との交点の許容(半径に比例する 1e-9。半径 1e9 のような非現実的な大きさでだけ、わずかに離れた線を接していると見なす。Snap と同じ許容)。折れ線の頂点が持つ bulge(取り込み時に円弧は点列に展開済みで、頂点に bulge は残らないので、起こらない)。
- **含めていないもの:** 暗黙の延長(境界を延ばした位置との交点)、Shift キーでのトリム⇔延長の切り替え、フェンス・窓での一括トリム、楕円・スプラインの切り取り、切り取る部分のゴム紐(どこが消えるかの先行表示)、文字・寸法・ブロックの中身の編集。
### オフセット・切断(Phase 12)の約束事: OFFSET・BREAK

**OFFSET(エイリアス O)** の流れ: 距離を数値で入力(`T` = 通過点)→ 図形をクリック → 写す側(通過点のときは、通過点)をクリック → 続けて図形をクリック …(Enter・Esc で終了)。1回ごとに図面へ反映する。**Undo は、1回の写しにつき1段階**。元の図形は変えず、**新しい図形を1つ、描画順の末尾に追加する**(レイヤー・色・線種・線の太さは、元の図形と同じ)。

**BREAK(エイリアス BR)** の流れ: 図形をクリック(**そのクリックの位置が第1点**)→ 第2点。`F` で第1点を指定し直せる(吸着した点が使える)。1回で終わる(Undo は1段階)。

- **図形を指すクリックは、吸着しない(`rawPoints`、Phase 11 と同じ):** 吸着すると、ほかの図形の端点などへ吸い寄せられて、指したい図形が決まらないため。そのため、BREAK の第1点は、クリックの位置を図形の上へ射影した点で、座標が少しずれる。正確な位置にしたいときは、`F` で吸着した点か座標を指定し直す。第2点、OFFSET の通過点は、吸着する。距離を指定した OFFSET の「写す側」は、側を示すだけなので、吸着しない。
- **クリックの位置の図形を探す(`app/document/picking.ts`):** TRIM・EXTEND・OFFSET・BREAK で共通。範囲が点の近くにあるものだけを距離で調べ、いちばん近い図形から順に、編集できるか・対象の種類かを見る。コマンドは、`AppEditing.pickEntity`(最後のクリックの許容距離で探す)を、クリックを受けた直後に呼ぶ。
- **対象にできる図形:** 線・円弧・円・折れ線(閉じたものを含む)。楕円・スプライン・文字・点は、理由つきで断る。読み取り専用の図形(ブロックの中身・寸法)も、断る(COPY と同じ規則)。非表示のレイヤーの図形は指せない。
- **OFFSET の幾何(`core/geometry/offset.ts`):** 側は、線・折れ線は進行方向の左 +1・右 -1、円・円弧は外側 +1・内側 -1。クリックした点が、いちばん近い線分の左右(円は、外か内か)で側を決める。図形の真上の点は、側が決まらないので断る。
  - 線: 同じ長さの平行線(水平・垂直の線は、座標がぴったり)。円・円弧: 同心。内側へ、距離が半径以上(結果の半径が `MIN_RADIUS` 未満)なら断る。
  - 折れ線: 各線分を動かし、隣り合う線分の交点で結ぶ(**外側の角は延ばして結ぶ**)。結び目が遠すぎる外側の角(頂点から結び目までが、距離の `MITER_LIMIT` = 10 倍を超える)は、頂点から 10×距離 の所で、角の二等分線に垂直に先端を切る。内側へ動かして潰れた線分(向きが逆になる・長さ0)は、外して結び直す(外れる線分が無くなるまで)。閉じた折れ線は、閉じたまま(出力は、元の頂点0の結果から始まる)。連続する同じ点は1つにする。
  - **検証:** 折れ線の結果は、(1) 自分自身と交差しない、(2) 元の折れ線から、距離以上離れている(正しいオフセットは、元の図形から距離未満の所を通らない)、を確かめる(丸め誤差の許容: 距離の 1e-6 倍 + 1e-9 + 座標の大きさの 1e-12 倍)。どちらかが崩れたら、壊れた形を作らずに、「この距離ではオフセットできません」と断る。(2) は、元の折れ線の線分を、連なりの順に二分した範囲の木で調べる(10万頂点の折れ線で、1秒未満。格子だと、細かい点列で、距離の内側に何千本も入り、数十秒かかった)。
  - 通過点(T): 距離と側を、点から決める。線は、点を通る平行線(直線までの垂直距離。線分の外でも)、円・円弧は、点を通る同心の円(中心からの距離 − 半径)、折れ線は、折れ線から点までの最短距離。点が図形の上(距離0)なら断る。
  - 取り込んだ折れ線は、円弧の膨らみが展開済みの点列なので、点列の上で行う(**真の円弧のオフセットとは、近似の細かさの分だけずれうる**)。自己交差する折れ線(8の字など)は、断る。
- **BREAK の幾何(`core/geometry/break.ts`):** TRIM と同じ「道」の仕組み(`trim.ts` の位置 s・`chainSlice`)で、2点の間を取り除く。点は、図形の上へ射影する(水平・垂直の線分は、クリックの座標をそのまま使う)。
  - 線・円弧・開いた折れ線: 2点を、道に沿った位置の順に並べて、間を取り除く。端の外に出た点は、端として扱う。結果は、2つ・1つ・0つ(全体を取り除く=図形を削除)。**2点が同じ位置なら、取り除く部分なしで、その点で2つに分ける**。両方の点が同じ端の外、または、端の上で、何も変わらないときは、断る。
  - 円: 第1点から第2点まで、**反時計回りに**取り除き、円弧にする(**図形の種類が、円から円弧に変わる**。ID は保つ)。2点が同じ位置なら断る。
  - 閉じた折れ線: 第1点から第2点まで、頂点の順に取り除き、開いた1本の折れ線にする(2点が同じ位置なら、その点で開く)。
- **反映(`app/document/offsetting.ts`・`breaking.ts`・`pieces.ts`):** OFFSET = 追加の1変更。BREAK = TRIM と同じ(`pieces.ts` を共有): 1つ残る=置き換え、2つに分かれる=置き換え + 追加(2つ目は新しい図形で、元の図形のすぐ上の描画順)、無くなる=削除。座標が有限でない結果は、拒否する。
- **元データとの対応(保存の Phase への申し送り):**
  - BREAK: TRIM と同じ(`reshaped: true`。2つに分かれたとき、**2つとも同じ元の記録を指す**。保存では、「`id` が元の記録のIDと同じ図形」が元の記録を置き換え、他は、元の記録の属性を引き継ぐ新しい記録)。円→円弧のときは、元の円の記録を、円弧の記録に置き換える。
  - OFFSET: 結果は新しい図形で、**`reshaped: true` つきで、元の図形の記録を指す**(元の記録の属性=レイヤー・色・線種・線の太さなどを引き継いだ、新しい記録として書く。形は、いまの形)。新しく描いた図形のオフセットには、付けない(新しい図形として書く)。元の図形自身は、変わらない(元の記録のまま)。
- **仮表示(ゴム紐):** OFFSET は、カーソルの側へ写した形。BREAK は、切断したあとに残る形。頂点が 2,000 を超える折れ線は、計算が重いので、元の図形の枠だけを表示する(`OFFSET_PREVIEW_VERTEX_LIMIT`)。
- **性能(実図面。1回、Undo 込み):** OFFSET 平均 約0.4〜78 ms・最大 約276 ms(19万図形。ほとんどは、図面への適用と Undo の時間)。BREAK 平均 約0.4〜88 ms・最大 約154 ms。線・円弧・円・折れ線を種類ごとに最大20個ずつ(折れ線は、頂点の多いもの2つを加える)、距離 5 と 1000、両側で試した(約8割が成功。残りは、内側へ大きすぎる距離などで、理由つきで断られ、図面は変わらない)。
- **Codex レビューでの修正:** (1) 検証用の格子で、座標の大きさ ÷ 格子の幅 が 2^53 を超えると、番号を進める操作が効かず、ループが終わらなかった(座標 1e20・線分の長さ 10 など)。格子の幅を、座標の大きさ ÷ 1e9 以上に広げる(巨大な座標では、粗くなって遅いだけで、結果は変わらない)。(2) BREAK の射影で、線の長さの二乗が桁あふれ(座標 1e154 超)すると、位置が 0(始点)になり、入力と違う所を切断していた。大きい方の成分で割って計算し、求められないときは、全体を断る。(3) 距離の検証の許容が、座標の大きさに比例(1e-12 倍)して、座標が大きいと距離を超え、検証が素通りしていた。係数を 1e-14 倍に絞り、許容が距離の半分以上になるときは、検証できないとして断る(fail-closed)。(4) 隣り合う線分が、逆向きに折り返して重なる(端以外で重なる)のを、自己交差として検出していなかった。検出する。(5) 円・円弧の中心を BREAK の点に指定すると、`atan2(0,0)` で 0° 扱いになっていた。中心の点は、理由つきで断る。(6) `isFinitePiece` が円を検査していなかった。検査する。(7) 側が決まらない点(図形の延長線の上)の案内文が、事実と違っていたので直した。
- **設計どおりとした指摘:** 折れ線の通過点(T)は、AutoCAD と同じく、**折れ線から点までの最短距離**で写す。最も近い所が線分の内側(垂線の足)なら、結果は点を通る。最も近い所が線分の端・頂点のときは、結果の線は、距離だけ離れるが、点そのものは通らない(例: 線分の端の外の点)。線(LINE)は、直線までの垂直距離なので、いつも通る。**同じ形でも、線(LINE)と、2頂点の折れ線で、端の外の点の結果が異なる**ことに注意。ID を、`apply` の前に払い出すのは、Phase 9 以降の流儀(`apply` は原子的。失敗すると、番号が飛ぶだけ)。
- **Codex 再レビュー(修正後の最終版)での修正:** (1) 検証用の格子の番号を、図形の左下(最小の座標)からの距離で数え、幅も、座標の大きさではなく**図形の広がり ÷ 1e9 以上**に保つ(前回の修正は、絶対座標で幅を決めていたので、座標 1e9 の位置の小さな図形で、細かい線分が同じ升に集まり、二次時間になっていた。3万頂点で 数十秒 → 0.2秒)。番号が安全な整数の範囲を超える・非有限のときは、全件走査に切り替える(防御。到達しない)。(2) BREAK の射影の割合が ±Infinity(点が、線分に比べて極端に遠い)でも、端へクランプして射影する(NaN だけを、求められないとして断る)。(3) `applyPieces` が、結果の図形がもとの `sourceRecord` を持っていても、いったん外して付け直す(新しく描いた図形に、古い対応が残らない)。
- **見送った・設計どおりとした指摘(再レビュー):** BREAK の端の判定の許容(線分の割合で 1e-12。長さ 1e6 mm の線で、端から 5e-7 mm 以内の点は端とみなす。Phase 11 と同じ許容)。ほぼ逆向きの隣接線分(外積が相対 1e-9 以下)を、重なっているとして断る(座標の精度で、重なりと区別できない鋭い折り返しは、断る=安全側)。距離の検証の許容が、原点からの距離に比例する(座標 1e9 mm で、1e-5 mm 未満の距離は断る。現実の座標[1e6 mm 以下]では、影響しない)。OFFSET の適用が失敗したあと、図形の選択へ戻る(側の再指定はできない。コマンドは、適用の成否を受け取らない設計で、AutoCAD と同じ流れ)。
- **含めていないもの(仕様外のため、事前の承認が必要):** OFFSET の Erase(元を消す)・Layer・Multiple、楕円・スプラインのオフセット・切断、BREAK の「1点で分割」専用コマンド(第2点 = 第1点で代用)、読み取り専用の図形のオフセット、折れ線の外側の角を円弧で丸めるオプション、前回の距離の記憶。
### フィレット・面取り(Phase 13)の約束事: FILLET・CHAMFER

**FILLET(エイリアス FIL)** の流れ: 半径を入力(**Enter = 前回の値**。初期値 0)→ 1つ目の線をクリック → 2つ目の線をクリック → 続けて1つ目をクリック …(Enter・Esc で終了)。**CHAMFER(エイリアス CHA)** は、距離1・距離2(どちらも Enter = 前回の値)を入力して、同じ流れ。1回ごとに図面へ反映し、**Undo は1回につき1段階**。`F` は全体表示(FIT)のエイリアスなので、使わない。前回の値は、コマンドの定義が持つ(`createFilletCommands()` で作り直すと初期値に戻る。画面では、1つの定義 `FILLET_COMMANDS` を使い続ける)。

- **対象(Phase 13 の範囲):** 線(LINE)と折れ線だけ。円弧・円・楕円・スプライン・文字は、理由つきで断る(クリックで指すときに、「線・折れ線が対象です」と断る。`AppEditing.pickEntity` の第3引数 `kind = "chain"`)。組み合わせは次の2つだけ:
  - **別々の2本の線:** 2本の線(延ばした直線)の交点を角にする。
  - **1本の折れ線の、隣り合う2本の線分:** 2回とも、同じ折れ線の線分をクリックする(閉じた折れ線の、最後の線分と最初の線分も隣り合う)。同じ線分を2回、離れた線分、2頂点の閉じた折れ線(往復する2本)は、断る。
  - 折れ線と別の図形、別々の折れ線どうし、同じ線を2回は、断る(仕様外・理由つき)。
- **クリックの位置の意味(吸着しない = `rawPoints`):** 2本の線では、**クリックした側の腕が残る**(交点から見て、クリックの位置と同じ側。4つの象限すべてを確認済み)。もう一方の側は、接点まで短くなる。線が交点に届いていなければ、接点まで**延びる**(常に、短く・延ばす。AutoCAD の既定と同じ。切り替えのオプションは作らない)。クリックが交点の位置そのもの(どちら側か決まらない)なら、断る。折れ線では、クリックは、**どの線分か**を決めるだけ(最も近い線分)。
- **FILLET の幾何(`core/geometry/fillet.ts`):** 角の内側の角度を θ として、角から接点までの距離 `t = r / tan(θ/2)`(`r (1 + cosθ) / sinθ` で計算する。直角で半径ちょうどになり、長方形の角に丸め誤差が入らない)。円弧の中心は、1つ目の接点から、1つ目の線に垂直に、2つ目の側へ半径だけ離れた所。円弧は、反時計回りの短い方(掃引 π − θ)。**接点が、短い方の線の端を越える、または端とぴったり同じ(残る長さが 0)ときは、「半径が大きすぎます」と断る**(2本の線)。平行・一直線上の2本(sin θ ≦ 1e-9)は断る。**半径 0**: 2本を交点で結ぶだけ(円弧なし)。
- **CHAMFER の幾何:** 角から、1つ目の図形の上に距離1、2つ目の図形の上に距離2の所を結ぶ線を足す(**距離1は、1つ目にクリックした図形の上**)。長さが足りないとき(距離 ≧ 残る長さ)は、「距離が長すぎます」と断る。距離は、2つとも 0(2本を交点で結ぶ)か、2つとも 0 より大きい数。**片方だけ 0 は断る**(線の上を動かすだけで、角にならないため)。
- **折れ線の頂点の置き換え:** 角の頂点を、FILLET は**円弧の点列**、CHAMFER は2つの頂点に置き換える。折れ線自身が置き換わるだけで、図形は増えない(ID・描画順・属性は、そのまま。ほかの頂点は、同じ点のまま)。円弧の点列は、**弦の誤差が半径の 1e-4 倍以下**(90° で約 56 本の線分)。取り込んだ折れ線は、もともと円弧が点列に展開済みなので、扱いは同じ(**真の円弧ではなく、点列の近似**)。接点が隣の頂点とほぼ同じ位置(割合 1e-9 以内)のときは、その頂点を使う(長さ 0 の線分を作らない)。半径(距離)0 は、すでに角でつながっているので、「変わりません」と断る。結果が、頂点不足(閉じた折れ線で 3 未満)になるときも、断る。
- **反映(`app/document/filleting.ts`):** 別々の2本の線 = **2本を置き換え + 円弧(面取りは線)を1つ追加**(描画順の末尾)、を1つの変更(`ChangeSet`)にする。半径(距離)0 のときは、置き換えだけ。新しい円弧・面取りの線の**レイヤー・色・線種・線の太さは、1つ目の図形と同じ**(置き換えた2本は、それぞれ自分の属性のまま)。読み取り専用の図形(ブロックの中身・寸法)・削除された図形は断る。座標が有限でない結果は拒否する(コアが先に弾くので、アプリ層の確認は防御)。断った操作は、図形のIDを使わない。
- **元データとの対応(保存の Phase への申し送り):** 置き換えた図形は、それぞれ自分の元の記録を指し、`reshaped: true`(Phase 10・11 と同じ)。**新しい円弧・面取りの線は、1つ目の図形の記録を指し、`reshaped: true`**(OFFSET と同じ規則。元の記録の属性を引き継ぐ新しい記録として、いまの形で書く)。新しく描いた図形(元データに記録が無い)には、どの図形にも付けない。`withReshapedRecord`(`pieces.ts`)が、この付け直しを一手に引き受ける(結果の図形が、もとの記録を持っていても、いったん外す)。
- **性能(実図面 5件。1回、Undo 込み):** 平均 約0.2〜52 ms・最大 約129 ms(19万図形。ほとんどは、図面への適用と Undo の時間)。折れ線 約 40 個(頂点の多いもの 2 つを含む)と、線の組 約 40 組を、半径 5・1000、面取り(5,5)・(3,8)で試した(約半数が成功。残りは、平行・長さ不足などで、理由つきで断られ、図面は変わらない)。5件とも、操作 → Undo で、元と同じ図形(同じオブジェクト・同じ順)に戻る。
- **変異テスト:** 計算・検証・対応づけ・コマンドの 25 か所を意図的に壊して、テストが落ちることを確認した(円弧の向き・腕の側・長さの検査・面取りの距離の入れ替え・隣の頂点の再利用・閉じた折れ線の継ぎ目・属性の取り違え・記録の取り違え・編集可否・ID の払い出し・前回の値、など)。1つだけ生き残ったのは、アプリ層の「座標が有限か」の確認(コアが先に弾くため、到達しない防御)。1つ目の変異で、読み取り専用の拒否のテストが、図形が平行なために別の理由で通っていたことが分かり、平行でない組に直した。
- **Codex レビューでの修正(指摘 7件: 正しい 5、一部のみ正しい 1、設計どおり 1):** (1) 角と同じ位置に丸まる微小な半径・距離(角 (1,1)・距離 1e-20 など)で、折れ線に**連続する同じ頂点**、2本の線に**長さ 0 の面取りの線・中心の無い円弧**ができた。置き換えた所の前後(手前の頂点 → 新しい頂点 → 次の頂点)で、連続する同じ位置を検出し、2本の線では、2つの接点が同じ位置なら断る(元の折れ線が、もともと持つ重複頂点は、対象外の場所なので調べない)。(2) 座標の桁が大きく(1e12〜1e16)、丸め落ちて、半径・接線の条件が崩れた円弧が成功していた。円弧の接点・点列が、中心から半径の 1e-6 倍以内の距離にあることを確かめ、崩れたら「座標の桁に比べて、半径(距離)が小さすぎる」と断る(fail-closed。座標 1e12 で半径 25 も、丸めの誤差が半径の 1e-6 倍を超えるので断る)。(3) 線分の長さ・距離の二乗が、座標 1e154 超で桁あふれし、線分の選択が先頭の線分に落ちていた。大きい方の成分で割って射影し、距離は `hypot` で求める。距離が求められない線分があれば、黙って飛ばさず、全体を断る。(4) 2本の線の外積を長さの積で割る式が、桁あふれ(1e155)・0 への潰れ(1e-200)で、交わる線を平行と取り違えていた。単位ベクトルの外積で判定する。(5) CHAMFER で「片方だけ 0」と断られたあと、距離2だけを聞き直し、距離1を直せなかった。**1つ目の距離から入力し直す**。(6) ID の払い出しを、例外を投げうる変更の組み立ての**あと**にした(組み立てに失敗しても、番号を使わない)。`apply` が失敗したときに番号が飛ぶのは、Phase 9 以降の流儀どおり。
- **設計どおり・見送った指摘:** 接点が隣の頂点とほぼ同じ位置(割合 1e-9 以内)のとき、その頂点を使う許容が、弦の誤差の上限(半径の 1e-4 倍)を破る、という指摘は、角度が 1e-5 rad より鋭いときだけ成り立つ(許容の動き ≦ 1e-9 × t = 1e-9 × r / tan(θ/2)、上限 = 1e-4 × r)。そのような鋭角の丸めは、実用にならないので、許容は変えない。変異テストで生き残った、距離の二乗の桁あふれ(座標 1e154 超)は、クリックが図形の近く(許容距離内)にあるので、到達しない。
- **含めていないもの(仕様外のため、事前の承認が必要):** 円弧・円が絡む FILLET・CHAMFER、平行な線の半円による FILLET、`P`(折れ線のすべての頂点を一括で丸める)・`M`(複数)・`R`(半径をコマンドの途中で変更)・`N`(トリムしない)、異なる折れ線どうし・折れ線と線の組み合わせ、離れた線分を結ぶ操作、面取りの角度指定(長さ + 角度)、結果のゴム紐(確定前の先行表示)。

### 文字・文字スタイル(Phase 14)の約束事: TEXT・MTEXT・TEXTEDIT・TEXTSTYLE

**コマンド:** `TEXT`(エイリアス `DT`)= 挿入点 → 回転角(角度の数値、または点。**Enter = 0度**。ダイナミック入力の角度欄が出る)→ 文字を入力(1行)→ 図形を1つ追加。`MTEXT`(`MT`)= 枠の1つ目の角 → 反対の角(**枠の幅**になる)→ 文字を入力(複数行)→ 図形を1つ追加。`TEXTEDIT`(`ED`)= 文字をクリック → 内容を直す。`TEXTSTYLE`(`ST`)= 文字スタイルの管理パネルを開く(図面が無くても開ける)。1回の追加・編集が **Undo の1段階**。ツールバーにも、同じ4つのボタン(文字・複数行文字・文字編集・文字スタイル)。

- **文字の入力パネル(`components/TextInputPanel.tsx`):** 文字の内容は、コマンドラインではなく、画面の小さなパネルで入力する。**TEXT は Enter で確定、MTEXT・複数行の編集は Ctrl+Enter で確定(Enter は改行)、Esc・キャンセルで取り消し**。IME の変換を確定する Enter・Esc は、パネルでは扱わない。空・空白だけの文字は、理由(「文字が空です」)を出して、パネルを開いたまま待つ。コマンド側は、画面に依存せず、段階が `editor: { multiline, initial }` を宣言するだけ(`ActiveCommand.textEditor`)。パネルで確定した文字は、ふつうの `TextInput` として、段階に渡る。
- **文字スタイル(`core/text/textStyle.ts`・`components/TextStylePanel.tsx`):** 名前・フォント・高さ・幅係数・斜体・水平配置(左・中央・右)・垂直配置(基準線・下・中央・上)の組。**Standard**(高さ 100 mm)は、名前の変更・削除ができない(値は変えられる)。パネルで、現在のスタイルの選択・値の編集・新規作成(現在の値から)・名前の変更・削除ができる。値の範囲: 高さ 0.001〜1e6 mm、幅係数 0.1〜10、名前 64 文字、スタイル 100 個まで(範囲外・不正は、理由つきで断り、スタイルは変わらない)。フォント名は、引用符・バックスラッシュ・制御文字・`;{}<>` を含まない 100 文字以内(CSS への埋め込みを防ぐ)。入力欄には候補(sans-serif・serif・monospace・MS ゴシック・MS 明朝・メイリオ・游ゴシック・游明朝)を出す。入っていないフォントは、ブラウザが代わりのフォント(sans-serif)で描く(エラーにしない)。
- **スタイルは、作成時の値のコピー(ユーザー承認済み):** 文字は、描いたときのスタイルの値(フォント・高さ・幅係数・斜体・配置)を、そのまま持ち、**スタイル名は記録するだけ**。スタイルを後で変えても、すでに描いた文字は変わらない(連動して変わる仕組みは、プロパティ・スタイル管理の Phase で検討する)。コマンドは、**始めた時点**の現在のスタイルを使う。スタイルの一覧は、**図面のデータではなく、利用者ごとの設定**として、このブラウザの localStorage に保存する(`cad-viewer.text-styles.v1`。読み戻した値は、信用せず `normalizeTextStyleTable` で検証し、不正なものは捨てる。保存先が使えなくても、動きは変えない)。図面ファイルへの保存・テンプレート・他の図面からの読み込みは、保存の Phase 以降。
- **データモデル(`types/cad.ts` の `CadText`、取り込んだ文字のデータは変わらない):** 任意の属性を足しただけ: `fontFamily`・`italic`・`styleName`・`boxWidth`(MTEXT の枠の幅)・`isMText`。**取り込んだ文字(TEXT・MTEXT。MTEXT は従来どおり TEXT に変換され、書式は捨てられる)には付かない**。MTEXT は、型は `TEXT` のまま、`isMText: true` と `boxWidth` を持つ(DXF への書き出しの Phase で、MTEXT として書く手がかり)。幅係数が 1 のスタイルでは、`widthFactor` を持たない(取り込んだ文字と同じ形)。
- **MTEXT の枠:** 反対の角が、1つ目の角のどちら側でもよい。**枠の左上**が基準になり、基準点は、水平の配置に応じた、枠の左端・中央・右端(上端)。垂直の配置は、常に「上」(枠の上に合わせる)。回転は 0。枠の幅が 0、または 1e9 mm を超えるときは、断る。
- **折り返し(`core/text/textLayout.ts`、描画と選択範囲が同じ関数):** `layoutTextLines` が、改行(`\n`)で分け、`boxWidth` があれば、その幅に収まるように折り返す。字幅は、実際のグリフ幅ではなく、**見積もり**(半角 0.65 em、全角 1 em。幅係数を掛ける)。半角は空白で区切った語ごと(語が枠より長ければ、文字ごとに分ける)、全角は1文字ずつ。句読点・閉じ括弧・長音・小さい仮名などは、行の先頭に来ない(前の文字に付ける)。行末の空白は、はみ出してよい。**1行に、必ず1文字は置く**(枠が1文字より狭くても、前へ進む)。枠が無い・0 以下・非有限、文字の大きさが正しくない、20 万文字を超える文字は、折り返さない(改行だけで分ける。極端な入力で重くならない)。10 万文字を約 1 秒未満で折り返せる。MTEXT(`isMText`)の外形の幅は、**文字が短くても、枠の幅**。枠を持たない文字(取り込んだ文字)は、Phase 13 までと同じ計算。見積もりが実際の字幅より広めなので、**枠の幅より手前で折り返される**ことがある(安全側。実際のグリフ幅の測定は、仕様外)。
- **折り返しの単位と外形(Codex レビューでの修正後):** 折り返しと、折り返した文字の外形は、**書記素**(結合文字・異体字セレクタ・ZWJ の絵文字・国旗・肌の色を、1文字とする単位)で数える(`Intl.Segmenter`。特別な文字が無い文字列は、コードポイントごとで高速)。書記素の幅は、最初のコードポイントの幅。枠を持たない文字(取り込んだ文字)の字幅の見積もり(`estimateLineWidthInEm`)は、Phase 13 までと同じ。**行頭禁則の文字(句読点・閉じ括弧・長音・小さい仮名など)は、前の文字が禁則の文字でなければ、枠からはみ出しても、前の文字と同じ行に置く**(連続しては、はみ出さない)。枠が文字より狭くても、1行に1文字は置く。**枠より広い行(1文字が枠より広い・禁則の文字のはみ出し)があるときは、外形の幅に、そのはみ出しを含める**(はみ出した部分も選択できる)。行末の空白は、外形に数えない。
- **文字の入力の確認(`core/text/textInput.ts`):** 制御文字(改行・タブ以外)を含む文字は断る。空白・ソフトハイフン・ゼロ幅・書式の制御・BOM だけの文字は、空として断る。タブは空白にする。断られた文字は、**入力パネルに残る**(パネルは、コマンドの状態が進むたびに作り直されるので、最初の文字として渡す。直して確定できる)。
- **文字スタイルの読み戻し:** 読む要素数に上限(スタイルの上限の 4 倍)があり、Standard が無いときは、補って、上限(100 個)を超えない(最後の1つを、あきらめる)。
- **回転角:** 度の数値は、**先に 360 で割った余り**にしてから、ラジアンにする(巨大な値で、掛け算が桁あふれして NaN にならない)。
- **パネルの操作:** 文字スタイルのパネルは、IME の変換中の Esc では閉じない。文字の入力パネルの Esc は、ボタンにフォーカスがあっても効く。
- **文字の編集との関係:** SCALE は、高さと一緒に枠の幅(`boxWidth`)も拡大する(折り返しの結果は変わらない)。MOVE・ROTATE は、枠の幅に触れない。MIRROR は、これまでどおり、文字を反転しない。STRETCH は、基準点が窓の中にあるかで動かす(従来どおり)。選択・窓選択・範囲は、折り返し後の外形で計算する。
- **TEXTEDIT(`app/document/texting.ts`):** 文字列だけを置き換える(位置・高さ・回転・レイヤー・フォント・枠の幅などは、そのまま)。**取り込んだ文字も直せる**。1行の文字は、改行が空白になり、複数行文字(または、もともと改行を含む文字)だけ、複数行にできる。空・長すぎる(10 万文字超)・内容が同じ・読み取り専用(ブロックの中身・寸法)・文字でない・削除された図形は、理由つきで断る。クリックは、吸着せず、文字だけを指す(`pickEntity` の kind = `text`)。
- **元データとの対応(保存の Phase への申し送り):** TEXTEDIT で書き換えた取り込み済みの文字は、**自分の記録 + `reshaped: true`**(いまの内容で、元の記録を置き換えて書く)。新しく描いた文字・MTEXT、新しく描いた文字の編集には、付けない(新しい図形として書く)。
- **性能(実図面 5件):** 取り込んだ文字の内容の書き換え(最大 200 個)→ Undo で、元と同じ図形(同じオブジェクト・同じ順)に戻る。1回 平均 約0.2〜93 ms・最大 約250 ms(19万図形。ほとんどは、図面への適用と Undo の時間)。範囲の計算は、200 個で 10 ms 未満。
- **変異テスト:** 折り返し・外形・変換・スタイルの検証・入力の確認・文字の生成・コマンド・編集の 31 か所を意図的に壊して、テストが落ちることを確認した(生き残りは、1度出た「幅係数 1 を省く」の確認を足して、0)。
- **Codex レビューでの指摘(9件: 正しい 8、再現せず・見送り 1):** (1) 枠より広い行が、外形に入らず、はみ出した部分を選べなかった → 外形に含める。(2) 枠が狭いと、行頭禁則の文字(「あ。」の「。」)が行頭に来た → はみ出しても、前の文字と同じ行に置く(連続しては、はみ出さない)。(3) 結合文字・ZWJ の絵文字・国旗が、途中で分かれ、幅が二重に数えられた → 書記素で数える。(4) 入力が検査で断られると、パネルが作り直されて、入力した文字が消えた → 断られた文字を、パネルに残す。(5) 文字スタイルのパネルが、IME の変換中の Esc で閉じた → 変換中は扱わない(keyCode 229 も)。(6) 角度 `1e308` で、掛け算が桁あふれして NaN の回転ができた → 先に 360 で割った余りにする。(7) ゼロ幅の文字だけ・制御文字を含む文字を、追加できた → 断る。(8) スタイルの読み戻しが、Standard を補うと上限を超え、巨大な不正配列を全部読んだ → 上限を守り、読む数も制限する。(9) 文字の入力パネルの Esc が、ボタンにフォーカスがあると効かなかった → パネル全体で受ける。**見送り・再現せず:** 文字スタイルの編集欄が、別の値の変更で作り直され、未確定の値が失われる、という指摘は、欄を離れた時点で確定され(高さを入力して、Enter を押さずに斜体を切り替えても、両方が反映される。E2E で確認)、再現しなかった。行末禁則(開き括弧が行末に来ない)は、仕様外として、実装していない。
- **含めていないもの(仕様外のため、事前の承認が必要):** 取り込み時の文字スタイルの反映(DXF の STYLE テーブルのフォント名・斜体角)、MTEXT の書式コード(色・下線・太字・段組み)、リーダー・マルチリーダー(別の Phase)、スタイルのテンプレート保存・他の図面からの読み込み、文字の Grip 編集・プロパティでの高さ・フォントの変更(Phase 18)、実際のグリフ幅の測定、文字への Snap(挿入点)、TEXT の繰り返し(1回で終わる)、ツールバーが狭い画面で、ボタンが窮屈になること(ボタンが 28 個に増えた。幅が足りないときの折り返し・スクロールは、別途の改善)。

### 寸法・寸法スタイル(Phase 15)の約束事: DIMHORIZONTAL・DIMVERTICAL・DIMALIGNED・DIMRADIUS・DIMDIAMETER・DIMANGULAR・DIMSTYLE

**コマンド:** `DIMHORIZONTAL`(`DH`、`DIMLINEAR`)・`DIMVERTICAL`(`DV`)・`DIMALIGNED`(`DAL`)= 1つ目の点 → 2つ目の点 → 寸法線の位置。`DIMRADIUS`(`DRA`)・`DIMDIAMETER`(`DDI`)= 円・円弧をクリック → 文字の側の点(直径は、その向きを決める点)。`DIMANGULAR`(`DAN`)= 1本目の線をクリック → 2本目の線をクリック → 弧が通る点(最初の段階で **Enter = 頂点・腕の上の点2つの3点指定**)。`DIMSTYLE`(`DST`)= 寸法スタイルの管理パネルを開く(図面が無くても開ける)。**1回の寸法が Undo の1段階**。寸法は1つ描くと終わる(繰り返さない)。ツールバーは、**「寸法▾」ボタン1つ**(クリックで、7項目のメニュー。外のクリック・Esc で閉じる)。

- **データモデル(`types/cad.ts` の `CadDimension`、type `"DIMENSION"`):** 寸法は、**線・矢印・数値を持たず、定義点とスタイルの値だけ**を持つ(`kind`・`p1`・`p2`・`p3?`・`position`・`rotation?`・`values`・`styleName?`、色・レイヤー・`lineDash` は他の図形と同じ)。線・矢印・弧・数値は、**表示のたびに、定義点から計算する**(`core/dimension/dimensionGeometry.ts` の `layoutDimension`)ので、測定値が古くならない。定義点は、水平・垂直・平行 = 起点 `p1`・`p2` と、寸法線が通る点 `position`(水平・垂直は、寸法線の向き `rotation` = 0 または π/2)、半径・直径 = 中心 `p1`・円周上の点 `p2`・文字の側の点 `position`、角度 = 頂点 `p1`・腕の上の点 `p2`・`p3`・弧が通る点 `position`。純粋な値だけで、JSON にそのまま直せる(保存の Phase で、DXF の DIMENSION と描画ブロック `*Dn` を `layoutDimension` の結果から作れる)。**Phase 16(連動寸法)は、参照図形を足すだけで、この形を変えない。**
- **取り込んだ DXF の寸法は、従来どおり**(描画済みの線に展開され、読み取り専用)。新しい `DIMENSION` 図形とは別。DXF の未対応の集計(`unsupportedBreakdown` の `DIMENSION`)も、そのまま。
- **スタイルは、作成時の値のコピー(Phase 14 の文字と同じ):** 寸法は、描いたときの寸法スタイルの値(文字の高さ・矢印の大きさ・小数桁(長さ・角度)・単位・単位の表示・補助線の間隔)を持ち(`values`)、**スタイル名は記録するだけ**。スタイルを後で変えても、描いた寸法は変わらない。色・レイヤー・線種は、図形そのものの属性になる(色は、スタイルが指定すればそれ、無ければ描くレイヤーの色)。スタイルは**コマンドを始めた時点**の値を使う。
- **寸法スタイル(`core/dimension/dimensionStyle.ts`・`components/DimensionStylePanel.tsx`):** 名前・文字の高さ(既定 100 mm)・矢印の大きさ(100 mm)・長さの小数桁(0)・角度の小数桁(1)・単位(mm・cm・m。図面の mm を換算して表示)・単位を数値に付けるか・補助線の間隔(50 mm)・色(`#rrggbb` または「レイヤーに合わせる」)・レイヤー(「現在のレイヤー」または名前)・線種(実線・破線・中心線・一点鎖線)。**Standard** は、名前の変更・削除ができない(値は変えられる)。値の範囲: 高さ・矢印 0.001〜1e6 mm、補助線の間隔 0〜1e6、小数桁 0〜8 の整数、名前 64 文字、スタイル 100 個まで(範囲外・不正は、理由つきで断り、スタイルは変わらない)。保存は、図面ではなく**利用者ごとの設定**として localStorage に(`cad-viewer.dimension-styles.v1`。読み戻した値は信用せず、`normalizeDimensionStyleTable` で検証し、不正なものは捨てる。読む数にも上限。保存先が使えなくても、動きは変えない)。スタイルが指定したレイヤーが無い・非表示のときは、理由を出して描かない。線種は、図面の線種の管理(Layer / Linetype の Phase)が入るまでの、**文字の高さに比例した4種の固定パターン**(`dimensionLineDash`。Phase 17 で、線種の管理に差し替える)。矢印は、線種に関わらず、実線で塗りつぶす。
- **配置の規則(`dimensionGeometry.ts` の先頭に記載):** 直線の寸法は、寸法線が `position` を通り、起点から寸法線までの距離が補助線の間隔より大きいときだけ補助線を引く(寸法線の先へ、矢印の半分だけ出る)。長さが矢印2本分に満たないときは、矢印を外側に出す(寸法線の外側へ矢印の2倍の線)。数値は、矢印の間に収まるとき(長さ ≥ 数値の幅 + 矢印2本分)は寸法線の中央の上、収まらないときは終点の外側。半径は、中心から `position` への向きの円周上に矢印の先を置き、そこから `position` まで線を引いて(矢印2本分より短ければ延ばす)、その先に数値を置く。直径は、中心を通る直線寸法(補助線なし)。角度は、**頂点から見て `position` の向きを含む側の角(0〜360度)**を測り、頂点から `position` までが弧の半径。腕が弧に届かないときだけ補助線を引く。数値は、線に沿って回転し、下から読める向き(-90度を超え90度以下)にそろえる。数値の幅は、文字(TEXT)と同じ見積もり(`core/text/textLayout.ts`)。
- **計算できない寸法(`layoutDimension` が null):** 長さ 0・重なる腕・中心と同じ点・有限でない値・桁あふれ・使えないスタイルの値。コマンドは、理由を出して断り、やり直せる。すでにある寸法がそうなったときは、描かず、範囲・選択は定義点で扱う(落ちない)。垂直・水平(90度の倍数)の向きは、`exactCosSin` で、ぴったりの値(`cos(90°) = 6e-17` の誤差を座標に入れない)。
- **選択・範囲(`core/geometry/entityGeometry.ts`・`Selection.ts`):** 寸法線・補助線・矢印への最短距離、**弧への最短距離(解析的。円弧 ARC と同じ。折れ線近似だと、半径 10000 mm の 90 度で、弦と弧が最大約 21 mm ずれて、クリックで選べない)**、**数値の外形(詰まった矩形)**の、最も小さいもので、選択する。窓選択は、全部の点が箱の中。交差選択は、実際の線分(点を順に結んだだけの折れ線ではない)と、数値の矩形で判定する。範囲(`entityBounds`)は、線・矢印・数値と、弧(48分割の点に、弧がまたぐ 0・90・180・270 度の極値の点を足したもの)を含む。
- **既存の編集との関係:** MOVE・COPY・ROTATE・SCALE・MIRROR は、定義点と(水平・垂直の)向きを動かす(`transformEntityGeometry`)。**SCALE では、文字の高さ・矢印の大きさなどのスタイルの値は変えない**(測定値だけが、倍率に合わせて変わる)。MIRROR は、向きを写し、数値は(計算で)読める向きになる。STRETCH は、水平・垂直・平行は、窓の中にある定義点だけを動かす(測定値が変わる。寸法線の位置だけが窓の中なら、寸法線が動く)。**半径・直径・角度は、全部の点が窓の中のときだけ移動し、一部だけのときは対象外**(円・角の意味が変わるため。「円弧・楕円・寸法 N 個は、一部だけが窓に入っているため、対象外」)。TRIM・EXTEND・OFFSET・BREAK・FILLET・CHAMFER の対象にはならず(「DIMENSION は、トリムできません」)、TRIM・EXTEND の境界にもならない。**Snap の対象にもならない**(端点・中点・交点・中心・垂線・接線・延長・最近点のどれも出さない。連動寸法の Phase で見直す)。新しく描いた図形なので、元データとの対応(`sourceRecord`)は付かない。
- **描画(`CanvasRenderer`):** 通常の図形・文字より**上**(選択の下)に描く(仕様 §23 の描画順)。線(寸法線・補助線・弧)は、色と線種ごとにまとめて1回で、矢印は、塗りつぶして、数値は文字として。寸法の形は、図形のオブジェクトごとに覚える(`WeakMap`。図形は、変更のたびに新しいオブジェクトになる)。選択した寸法は、線・矢印・数値とも、強調色。
- **角度寸法を、2本の線から作る(`core/dimension/dimensionConstruct.ts`):** 2本の線(無限に延ばした直線)の交点が頂点。4つの角のうち、弧が通る点の向きを含む角を測る(`angularFromLines`)。腕の上の点は、その向きの、線の端のうち頂点から遠い方(線がその向きに伸びていないときは、わずかな長さ)。ほぼ平行(0.001度未満)・長さ 0 の線は、断る。**弧の半径が、線の頂点に近い端より手前のとき、補助線は引かない**(弧は、線から離れて浮く。簡易な規則)。
- **性能(実図面 5件):** 実際の線・円・円弧に、寸法を最大400個足して、形の計算 約2〜6 ms、1回の追加(Undo 1段階)約3〜97 ms(19万図形)、範囲の計算(寸法込み)約5〜35 ms、Undo で、元と同じ図形・同じ順に戻る。寸法 **10,000 個**で、形の計算 約55〜90 ms、範囲 約75〜110 ms、1点の選択 約55〜83 ms(索引なし)。
- **変異テスト:** 形・整形・スタイル・変換・STRETCH・Snap・TRIM・選択・描画・コマンド・作図の 55 か所を意図的に壊して(Codex 修正で 6 か所を足し、61 か所)、テストが落ちることを確認した(最初に生き残った 5 件=矢印の向き、補助線の間隔(角度)、桁あふれの確認、交差選択の線分、円・円弧の指定 は、テストを足して、0)。
- **Codex レビューでの指摘(6件: 正しい2、一部のみ正しい1、設計どおり2、簡易な規則のまま1):** (1) 角度寸法で、腕のベクトルが桁あふれして `Infinity` になっても検査を通り、`atan2(1e308, Infinity) = 0` のような誤った向きで角度を返した → 腕・位置のベクトルが有限でないときは、計算できないものとして断る。(2) 弧の選択が折れ線で、半径が大きいと選べず、範囲が弧の極値に届かなかった → 弧への距離を解析的に、範囲に極値の点を足す。(3) **一部のみ正しい:** 寸法の `values`(単位・小数桁・単位の表示)を `layoutDimension` が確かめず、不正だと `?` が寸法の値として出る。値は今は、検証済みのスタイルからだけ作られる(読み込みの境界は、保存の Phase)が、安く防げるので、単位・小数桁・単位の表示も確かめて、不正なら null にした。**設計どおり:** (4) 計算できない寸法が、描かれないのに、定義点を結ぶ線で選べる → 選べないと、見えないまま消せない寸法が残るため、意図的(STRETCH で長さ 0 になっても、選んで消せる。Undo もできる)。非有限の点は、これまでの図形と同じ方針(どこにでも交差する範囲)で扱う。(5) 半径で、文字の側の点が中心と同じとき、線・文字が中心側に向かう → 「矢印の先から、指定された点まで線を引き、その先に数値」という規則のとおり。**簡易な規則のまま:** (6) 角度が小さいとき、矢印を外に出すが、外側の線は足さず、数値も弧の中央の上に置くため、重なりうる → 直線の寸法のように、数値を外側へ移す規則は、Phase 15 の範囲外とし、既知の制限とした。テスト不足の指摘は、Codex に既存テストを渡していないための誤判定(再現例は、テストに足した)。変異テストは、修正の 6 か所を足して、合計 61 通りで、生き残り 0。- **含めていないもの(仕様外のため、事前の承認が必要):** 連動寸法・参照切れの警告・再関連付け(Phase 16 で実装。下の節)、寸法の数値の上書き、基準寸法・直列寸法、引出線(Leader)、公差・換算寸法・座標寸法・弧長寸法、グリップでの寸法線・数値の位置の移動と、プロパティでの編集(Phase 18)、寸法への Snap、スタイルの変更を、すでにある寸法へ反映する操作、取り込んだ DXF の寸法を、編集できるようにすること、DXF・保存への書き出し(Phase 21・22)、レイアウトの尺度への追従(Phase 24)、ツールバーが狭い画面で窮屈なこと(「寸法▾」で、増えるボタンは1つ)。
### 連動寸法(Phase 16)の約束事: 参照・追従・Broken Reference・DIMREASSOC

**考え方:** 寸法が、参照する図形(**Reference Entity**)と、その図形の上の位置(**Reference Point**)を持つ。参照した図形が編集で変わると、寸法の測る点が追従する。参照した図形が消えたら、**Broken Reference** として警告する。

- **データモデル(`types/cad.ts`):** `CadDimension.refs?: DimensionRef[]`(無い・空なら、連動しない寸法。Phase 15 までの寸法はそのまま)。`DimensionRef = { slot, id, anchor, broken? }`。`slot` は、どの定義点(または図形)か: `p1`・`p2`・`p3`(点)、`figure`(半径・直径の円・円弧)、`line1`・`line2`(角度の2本の線)。`anchor` は、図形の上の位置: 線の `start`・`end`・`mid`、円弧の `start`・`end`・`mid`・`center`、円の `center`、折れ線の `vertex`(番号)、図形そのものを指す `whole`。**参照できるのは、線・円弧・円・折れ線だけ**(線分の中点・四半円点・交点・楕円・スプライン・文字は、対象外)。純粋な値だけで、保存の Phase でそのまま持てる。
- **追従の仕組み(`app/document/associativity.ts`、`DocumentSession.apply` に集約):** すべての編集は `apply` を通る。`apply` が、変更(`ChangeSet`)を、まず `planAssociation` に通し、**参照している寸法の置き換えを、同じ変更の後ろに足して**、1つの変更として適用・記録する。だから、**Undo は1回で、追従ごと戻り**、Redo も同じ(履歴には足したあとの変更が入る。Undo・Redo 自体は、記録済みの変更を反転・再適用するので、追従を計算し直さない)。個々の編集コマンドは、変えていない。追従する寸法が無い変更は、**渡した変更をそのまま返す**(削除だけ・追加だけの変更の高速な経路を保つ)。追従を計算できなかったときは、中途半端に適用せず、理由つきで失敗する。「図形の ID → それを参照する寸法」の逆引きは、図形の配列ごとに1回だけ作る(単純な走査)。
- **追従の規則(`core/dimension/dimensionFollow.ts`。1つの変更の後の状態で、寸法ごと・参照ごとに決める):**
  - 参照した図形が**置き換えられた** → 測る点を、新しい図形の位置に直す(追従)。MOVE・ROTATE・SCALE・MIRROR・STRETCH・TRIM・EXTEND・BREAK・FILLET・CHAMFER のすべて。**TRIM・BREAK・EXTEND で端が動いても、元の ID の線の start・end に付いたまま追従する**(承認済み)。
  - 参照した図形が**削除された**・その位置が無くなった(種類が合わない・番号が範囲外・2本の線が平行になった)→ 参照を **broken** にする。測る点は、最後の位置のまま。**頂点の数が変わった折れ線(FILLET・CHAMFER・BREAK など)への参照は、broken にする**(承認済み。番号がずれて、別の頂点に黙って付くことを防ぐ)。
  - 参照した図形が置き換えられても、**同じ変更で、寸法自身が、その測る点を、図形の新しい位置と食い違うように動かしていた**ときは、寸法の編集を残して、その点の参照を解除する(図形と寸法を、別々の量で動かしたとき。引き戻さない)。寸法線の位置(`position`)だけを動かしたときは、解除せず、追従する。
  - 参照した図形が**変わっていないのに、寸法の測る点が、その位置から外れた**(寸法だけを MOVE・ROTATE・SCALE・MIRROR・STRETCH した)→ **その点の参照を解除する**(承認済み)。図形の見た目は、動かしたとおり。「関連付けを、動かした点について解除しました」と知らせる。寸法線の位置(`position`)だけが動いたときは、解除しない。
  - 寸法と図形を**一緒に**動かしたときは、寸法の点が、動かした図形の位置に一致しているので、解除されない(追従した結果と同じ位置)。
  - すでに broken の参照は、自動では直さない(付け直しは DIMREASSOC)。
  - **寸法線の位置(`position`)は、追従では動かさない**(測る点だけが、図形に付いていく)。角度は、2本の線から頂点・腕を求め直す(弧が通る点の向きを含む角を測る。線が大きく動いて、別の角に入ることがある)。半径・直径は、円の中心と半径に追従し、円周上の点の向きは保つ。
- **作図時の付け方(承認済み):** 半径・直径は、クリックした円・円弧を参照する。角度(2本の線)は、2本の線を参照する。水平・垂直・平行・角度(3点)は、**確定のときに、測る点が、図形の端点・中点・中心・頂点に一致していれば、自動で参照にする**(`findAnchorsAt`。スナップで吸着した点は、図形の座標そのものなので一致する。許容は 1e-6 mm + 座標の大きさに比例する分)。一致しない点は、固定の点のまま。**共有する角では、描画順で最前面の図形に付く**。表示中のレイヤーの図形だけが対象。全図形の範囲を1回だけ計算して、点が複数でも、1回の走査(19万図形で、2点なら約30 ms)。付いた箇所の数を、メッセージで知らせる。ゴム紐では、参照を探さない(確定のときの1回だけ)。
- **DIMREASSOC(`DRE`、「寸法▾」の「関連付け」):** 寸法をクリックして、参照を付け直す。水平・垂直・平行は、測る点を1つずつ、図形の端点・中点・中心・頂点をクリックして付ける(**測る点が、そこへ動く**。AutoCAD の DIMREASSOCIATE と同じ。Enter = 今の点のまま。今の点が図形の位置に一致していれば、付く)。半径・直径は、円・円弧をクリック(向きは保つ。Enter = 変更なし)。角度は、2本の線をクリック(Enter で、頂点・腕の3点を付け直す)。**Phase 15 までの寸法を連動にするのにも使える**。形が計算できない結果、実在しない図形・位置、測る点と一致しない参照は、断る(`app/document/dimensioning.ts`)。1回が Undo の1段階。
- **Broken Reference の警告:** 参照が切れた寸法は、**赤(`#ff3b30`)で描く**(選択のハイライトが優先)。プロパティに `Associativity: Broken Reference` と、参照ごとの `Reference p1: <ID> <位置>(broken)`。編集のメッセージにも「寸法 N 個の参照が切れました(Broken Reference。赤で表示します。DIMREASSOC で付け直せます)」(`DocumentSession.takeNotice()` を、`App.applyEdit` が続けて表示する)。Undo で、図形と一緒に戻る。
- **複写:** 寸法を複写すると、**連動しない寸法**になる(複写の測る点が、参照した図形から外れたまま、参照だけが残ると、図形が変わったとき、複写が引き戻されるため)。図形と寸法を一緒に複写しても、複写の寸法は連動しない。
- **一括適用の拡張(`core/history/apply.ts`):** 削除だけ(または追加だけ)の大きな変更に、置き換えが続く変更(追従が足した置き換え)は、前半を1回の走査、後半を1件ずつ、で適用する(`applyBulkThenReplaces`)。足さないと、置き換えが1つ付いただけで、19万図形の散らばった10万件の削除が、数十秒の経路に落ちる。1件ずつの適用と、結果もエラーの文言も同じことを、ランダムなテストで確かめる。
- **制限(既知):** 折れ線の線分の中点・四半円点・交点は、参照にならない(点は固定のまま)。共有する角で、意図と違う図形に付くことがある(プロパティで確認し、DIMREASSOC で直す)。線の大きな回転で、角度寸法が別の角へ移ることがある。参照が broken の寸法は、自動では直らない。取り込んだ図形(読み取り専用のブロックの中身を含む)も参照できる(編集されないので、追従しない)。
- **性能(実図面 5件):** 200個の線に、寸法を付けて、**追従つきの移動**が、19万図形で約190 ms(小さい図面は 4〜15 ms)、ストレッチ 約140 ms、**9.5万図形の一括削除**(参照された線を含む)が約350 ms(高速な経路を保つ)。いずれも、Undo で元と同じ図形・同じ順に戻る。400点の参照探索は、19万図形で約0.6秒(2〜3点なら数十 ms)。
- **変異テスト:** 追従・切れた判定・参照の探索・履歴・コマンド・再関連付け・描画の 46 か所を意図的に壊して、テストが落ちることを確認した(最初に生き残った 2 件は、テストを足して 0。残る 2 件は、結果が変わらない等価な変更: 削除した図形の `after` の持ち方、後半の種類の検査)。
- **Codex レビューでの指摘(9件: 正しい5、一部のみ正しい3、見込み違い1。誤判定のテスト不足の指摘を除く):** (1)(一部のみ正しい)図形と寸法を別々の量で動かすと、寸法が図形の位置へ引き戻される → 現在のコマンドは、選んだ全員に同じ変換を掛けるので、通常は起きないが、規則の一般化として、寸法自身がその点を食い違うように動かしていたら、編集を残して解除する。(2)(**正しい**。実際のバグ)角度寸法で、片方の参照がすでに切れていると、参照が重複し、もう片方の図形が削除されても切れなかった → 2本の線の組を、参照のループとは別に、1回だけ決める。(3)(正しい)1回の変更の途中で、折れ線の頂点の数・閉じ方が変わると、始めと終わりが似ていて、別の頂点に付く → 変更の途中の構造変化を記録(`restructured`)し、頂点の参照を切れた扱いにする(閉じ方が変わった場合も)。頂点の数・閉じ方が同じまま、頂点が入れ替わる編集は、検出できない(既知の制限)。(4)(一部のみ正しい)作図・再関連付けの途中で、図形が変わると、不整合が残る → 作図の途中に、ほかの編集は入れない(コマンドは1つずつ。Undo のボタンも、コマンドを置き換える)ので、作図では到達しない。再関連付けの検査(`dimensioning.ts`)は、円の中心・半径、2本の線の頂点・腕まで確かめるように強化した。(5)(正しい)巨大な座標(1e12 mm)で、許容が約 1 mm になり、離れた点を一致とみなす → 許容に上限(1e-4 mm)を付けた。(6)(正しい)`NaN` の点が、円の参照と「一致」と判定される → 比較を「収まったら一致」の形にして、非有限は不一致にした。(7)(正しい。極端な値)線の中点が、1e308 付近で桁あふれして参照が切れる → 桁あふれしない計算にした。(8)(**見込み違い**)参照の逆引きの再構築が、図面の大きさに比例する → 20万図形で、追従の計算は 0.78 ms で、`apply` 自体(30 ms)の 2.6%。(9)テスト不足の指摘は、Codex に既存テストを渡していないための誤判定(再現例は、テストに足した)。変異テストは、修正の 17 か所を足して、合計 63 通りで、生き残りは、結果が変わらない等価な変更 4 つだけ(削除した図形の `after` の持ち方、後半の種類の検査、`restructured` の引き継ぎ、閉じ方の二重の検査)。- **含めていないもの(仕様外のため、事前の承認が必要):** 交点・四半円点・折れ線の線分の中点・文字・楕円・スプラインへの関連付け、中心線(§31)・引出線(§37)の連動、寸法を寸法に関連付けること、XREF の図形への関連付け、参照のグリップ編集・プロパティでの編集(Phase 18)、切れた寸法の自動修復、複写した寸法の、複写先の図形への付け替え、保存・DXF への書き出し(Phase 21・22)。
### レイヤー・線種・線の太さ(Phase 17)の約束事: LAYER・LINETYPE・LINEWEIGHT・LTSCALE・LAYMOVE・ByLayer

**考え方:** レイヤーに、色・線種・線の太さを持たせ、図形が「レイヤーに従う(ByLayer)」属性を持てるようにする。レイヤーの設定を変えると、ByLayer の図形も、**同じ変更の中で**追従する(Undo は1回で、レイヤーも図形も戻る)。

- **データモデル(承認済みの方針: 図形に印を持たせ、レイヤー変更で図形を書き換える):**
  - `CadLayer` に `lineType?`(線種表の名前。無ければ実線)・`lineWeight?`(1/100 mm。無ければ既定=細線)。`CadDocument` に `lineTypes`(線種表: 実線、取り込んだ図面の LTYPE、取り込まれていない標準の線種 約12種の順)・`ltScale`(全体の線種尺度。`$LTSCALE`)。`CadModel` にも同じ `lineTypes`・`ltScale`(往復しても同じ)。
  - 図形に `lineTypeScale?`(図形ごとの線種尺度。DXF の 48。1 以外のときだけ。破線が無い間も失わないため、破線とは別に持つ)。図形に `byLayer?`(ビット: 色=1・線種=2・線の太さ=4。`core/style/byLayer.ts`)。**図形の `color`・`lineDash`・`lineWeight` は、従うべき値を解決済みで持ち続ける**(描画・選択・範囲の計算は、変えていない)。印が立っている属性だけが、レイヤーの設定に従う。印の無い属性は、図形自身の指定(ByObject)。文字・点は色だけ、寸法は色と線種(線の太さは持たない)。
  - 破線の鍵は `名前(大文字)@尺度`(尺度 = 全体の線種尺度 × 図形ごとの尺度)。図形ごとの尺度は、鍵と `ltScale` から取り戻す(`entityDashScaleOf`。誤差は有効数字12桁に丸める)。寸法の鍵(`dim:…`)など、別の形の鍵は、全体の尺度の変更で触らない。
- **取り込み(`io/dxf/DxfParserAdapter.ts`)での印:** 図形の色が、レイヤーの色で決まった(色番号が 256・未指定で、ByBlock の継承でない)とき色の印、線種が未指定・BYLAYER のとき線種の印、線の太さが未指定・-1 のとき太さの印を付ける(ByBlock・既定値 -3・数値の指定は、図形自身の指定として、印なし)。**展開済みのブロックの中身も、同じ規則**(図形のレイヤーは、ブロック内のレイヤー "0" を挿入先のレイヤーに読み替えたあとの値)。ByBlock で継承した値は、レイヤーに従わない(ブロックの扱いは Phase 20)。レイヤー表の線種・線の太さ(実線・既定値は持たない)と、LTYPE 表・`$LTSCALE` も、モデルに持つ。
- **DWG から変換した図面の制限(実図面で確認):** LibreDWG で変換した DXF は、図形の色などを、ByLayer ではなく数値で書いていることが多く(実図面の `layout-dwg` は印が 0 個、`smmx-dwg2000` も 0 個)、**その図面では、レイヤーの設定を変えても、図形は追従しない**。追従する図形が無いときは、メッセージで理由を知らせる(「追従する図形はありません: …DWG から変換した図面では、元の ByLayer の指定が失われています」)。色がレイヤーの色と同じ図形を、ByLayer とみなす推定は、AutoCAD の意味と食い違うことがあるので、入れていない(要望があれば、別途相談)。
- **履歴(`core/history/changeSet.ts`・`apply.ts`):** `ChangeSet` に、`layerAdd`・`layerRemove`・`layerReplace`(名前・色・線種・線の太さ)・`ltScale` を足した。位置は、その変更の直前のレイヤー表での位置。**原子的**: 検証はすべて通すか、何も変えないか。`layerRemove`・`layerReplace` は、その位置のレイヤーの定義(名前・色・線種・太さ。**表示は除く**)が一致することを確かめる。**図形のレイヤーが存在するかは、レイヤーの名前の集合が変わる変更では、最後にまとめて確かめる**(Undo は逆順に適用するので、図形の置き換えが、レイヤー表の変更より先に来る)。名前の集合が変わらない変更は、従来どおり、1件ずつ、番号つきの文言で断る。使用中のレイヤーの削除・図形を付け替えない名前変更は、「存在しないレイヤーを参照することになります」で断る。
- **レイヤーの表示・非表示は、履歴の対象外の表示設定:** 表示の状態は、ドキュメントのレイヤー表に持つ(これまでの画面の状態から移した)が、`DocumentSession.setLayerVisible` で、履歴・未保存の状態に入れずに切り替える(購読者には `kind: "view"` で知らせる。描画用のモデルは作り直さない)。レイヤーの変更を適用・Undo・Redo しても、いまの表示の状態を保つ。
- **操作(`app/document/layering.ts`。1回が Undo の1段階):**
  - `createLayer`: 名前(前後の空白を取る。空・256文字以上・`< > / \ " : ; ? * | = ` ` と制御文字・大文字小文字を無視した重複は断る)・色(#rrggbb)・線種(線種表にあるもの)・線の太さ(標準の値)を検証して、表の末尾に足す。
  - `editLayer`: 色・線種・線の太さ。**変えた属性だけ**を、そのレイヤーの、印が立っている図形に反映する(色だけ変えて、線種まで作り直さない。図面に定義が無かった線種の図形に、標準の破線が付くのを防ぐ)。同じ設定は「変更がありません」。追従した数を知らせ、0 のときは理由を知らせる。
  - `renameLayer`: 名前を変え、そのレイヤーの図形を、同じ変更で付け替える。**レイヤー 0 は変えられない**(ブロックの中の "0" の図形が、挿入先のレイヤーに従う規則のため)。大文字小文字だけの変更は許す。
  - `deleteLayer`: **図形があるレイヤー・現在のレイヤー・レイヤー 0・最後の1つは削除できない**(図形を消さず、図形が、存在しないレイヤーを指すこともないように)。
  - `moveToLayer`(LAYMOVE): 編集できる図形だけ(除いた数と理由を知らせる)。印が立っている属性は、移した先のレイヤーの設定に従う。すでにそのレイヤーの図形は、数えて、除く。非表示のレイヤーへ移すと、見えなくなる旨を知らせる。
  - `setLineTypeScale`(LTSCALE): 1e-6〜1e6。破線(鍵が `名前@尺度`)の図形すべて(ByLayer でないものも)の長さを、新しい尺度で作り直す。
- **作図:** 新しい図形(線・ポリライン・長方形・円・円弧)は、現在のレイヤーの色・線種(破線)・線の太さ(0.27 mm を超えるもの)を解決済みで持ち、**3つとも ByLayer**(`DrawTarget` が `lineDash`・`lineWeight`・`byLayer` を持つ。`drawingStyleOfTarget`)。文字は色だけ。破線は、図面の線種表と全体の線種尺度から作る(`createDashFactory`。同じ線種・尺度は同じオブジェクトを共有)。複写・TRIM などで作る図形は、もとの図形の印を引き継ぐ(属性の複写)。
- **寸法スタイルの線種:** 値に `bylayer`(レイヤーに従う)を足し、**既定にした**。寸法は、色(スタイルが色を指定していないとき)と線種が、描くレイヤーに従う。すでにブラウザに保存してある `Standard` スタイルの `continuous`(実線)は、そのまま、自身の指定の実線(スタイルの線種を `bylayer` に変えると、従う)。
- **画面:** 左の Layers 欄の「管理…」と、コマンド LAYER(LA)・LINETYPE(LT)・LINEWEIGHT(LW)で、**レイヤー管理パネル**(`components/LayerManagerPanel.tsx`。レイヤー・線種・線の太さの3つの部分)を開く。レイヤーの行: 色(選び終わったとき1回だけ反映)・線種・線の太さ・名前・移動(選択中の図形を移す)・削除。線種の部分は、見本と全体の線種尺度(LTSCALE)。LTSCALE・LAYMOVE は、コマンドラインからも。プロパティに、`Color`・`Linetype`・`Lineweight` を、ByLayer のものには `(ByLayer)` を付けて表示する。現在のレイヤーが、なくなったとき(作成を Undo したなど)は、初期値(レイヤー 0 など)にする。レイヤーの名前変更・削除で、その名前を指定している寸法スタイルがあれば、直すよう知らせる(自動では直さない。寸法スタイルは、図面の外の設定のため)。
- **保存の Phase への申し送り:** 印が立っている属性は、保存では、図形の色 256(BYLAYER)・線種 BYLAYER・線の太さ -1 として書く(解決済みの値は書かない)。レイヤー表(名前・色・線種・線の太さ)と LTYPE 表・`$LTSCALE` も、書き出す。名前変更は、レイヤー表と、図形の `layer`(展開済みのブロックの中の図形を含む。**ブロック定義の中の図形が、元の名前を持っている**点に注意。Phase 20 で扱う)の両方を直す。色などの属性だけが変わった取り込んだ図形は、`sourceRecord` は変わらない(形は同じ)ので、保存では、図形の `layer`・`byLayer`・`color`・`lineDash`・`lineWeight` を、元の記録と比べて書き換える。
- **既知の制限:** 全体の線種尺度の変更は、図形ごとの尺度が 1 でない図形でも、尺度の比を保つ(図形が持つ `lineTypeScale`、無ければ破線の鍵から取り戻す)。作成したレイヤーを非表示にして、作成を Undo・Redo すると、表示に戻る。BYBLOCK の図形・ByBlock から継承した値は、レイヤーに従わない。線種の自作・`.lin` の読み込み、レイヤーのロック・フリーズ・フィルタ・グループ・状態の保存、図形ごとの線種尺度・色・太さの一括変更(Phase 18)、レイヤーの透明度・印刷スタイル(Phase 25)は、含めていない。
- **性能(実図面 5件。`src/regression/edit.perf.regression.test.ts` の「layer edits」):** 19万図形・図形が最も多いレイヤー(3.4万図形)で、色の変更 約140 ms、線種+線の太さ 約70 ms、名前変更 約200 ms、**全体の線種尺度の変更(全図形を走査) 約500 ms**、5万個の図形の別レイヤーへの移動 約270 ms。いずれも Undo で元と同じ図形・同じ順に戻る。10万図形の図面でも、50〜230 ms。
- **変異テスト:** 履歴・規則・線種表・レイヤー操作・取り込み・作図の 72 か所を意図的に壊して、テストが落ちることを確認した(最初に生き残った 8 件=重複名の検査、定義の一致[線種・太さ]、線種・太さの変更の検出、変えた属性だけの再評価、レイヤー 0 の削除、別の形の鍵を触らない分岐 は、テストを足して 0。1 件は、置き換えの文字列が改行で合わず未適用だったので、1行に直して確認)。Codex の修正の 7 か所を足して、合計 79 通りで、生き残りは、結果が変わらない等価な変更 1 つだけ(尺度の積の検査。`normalizeDashPattern` が、無限大・0 を、すでに断る)。
- **Codex レビューでの指摘(7件: 正しい4、一部のみ正しい1[見送り]、正しいが影響小[見送り]1、見込み違い1):** (1)(正しい)図形ごとの線種尺度が、実線の間に失われる(尺度 2 の破線の図形を、実線のレイヤーへ移し、破線のレイヤーへ戻すと、尺度 1 になる) → **`lineTypeScale`(DXF の 48)を、図形が破線とは別に持つ**ことにした(1 以外のときだけ。取り込み時に付ける)。追従・全体の尺度の変更は、図形が持つ尺度を優先する。(2)(**一部のみ正しい・見送り**)作ったレイヤーを非表示にして、作成を Undo → Redo すると、表示に戻る → 表示は履歴の対象外の設定で、再作成したレイヤーが表示されるだけ(図形は無い)。履歴に表示を持たせると、「表示は Undo に入れない」方針と食い違うので、既知の制限とした。(3)(正しい。極端な値)尺度の積が桁あふれ・桁落ちして、鍵が `NAME@Infinity` になる → 積が有限の正の数でなければ、破線にしない(実際の破線は、`normalizeDashPattern` が、すでに断るので、結果は同じ。防御として足した)。(4)(正しい)鍵の `@` の後ろが正の数なら、別の用途の鍵も線種の鍵として受ける → 鍵の名前の部分が、破線の名前と一致するものだけを対象にした。(5)(**見込み違い**)大量のレイヤー編集が、性能・メモリの負荷になる → 測定済み(19万図形・3.4万図形のレイヤーで 70〜500 ms)。履歴に積むのは、変わった図形だけで、図形の複製は持たない。(6)(正しいが影響小・見送り)現在のレイヤー A を B に名前変更して Undo すると、現在のレイヤーが、A でなく初期値(レイヤー 0)になる → 見えているレイヤーが 0 になるだけで、描く先は、画面の表示(★)のとおり。(7)(正しい)ByLayer の線の太さを、細線から細線(0.13 → 0.18)に変えると、「図形自身で指定している」と、誤った理由を出す → 印のある図形の数を数えて、「見た目が変わりません」と知らせる。保存のコードは、Phase 22 のため、判断できないという注記のとおり。
## 新しいコードを置く場所の決め方

1. 画面に関係なく、CAD としての計算や状態の変更か → `core/`
2. ファイル形式(DXF、DWG、将来の独自形式・PDF)に関わるか → `io/`
3. 「どのコマンドが、何をするか」など、画面に関係しないアプリの動きか → `app/`
4. 画面の部品や、マウス・キーボードの扱い、ワーカーの起動か → 画面の側(今は `cad-view/`、`components/`、`App.tsx`)

迷ったら、下の層(`core/`)に置けないかを先に考えます。下の層に置いたほうが、テストしやすく、壊れにくくなります。

## 今後の方針: 編集の結果を保存へ渡す方法(Phase 2・3・保存の Phase で具体化)

編集(コマンド、Undo)は `core/` に、保存(元データへの差分の適用)は `io/` にあります。`core/` は `io/` を読み込めないので、次の形でつなぎます。

- `core/` は、**ファイル形式に依存しない「変更の内容」**(追加・削除・変更した図形のID と、変更前後の図形)を作って返す。Undo も、この変更の内容を記録する。
- `io/` は、その「変更の内容」を受け取り、図形のID から元データの記録を引いて、差分(削除・差し替え・追加)に変換して適用する。
- 両者を呼び出して結びつけるのは、画面の側(将来は、画面と中核の間に置く「アプリの層」)。

## まだ整理していないもの(後の Phase で行う)

- 画面の側(`cad-view/`、`components/`)は、今の場所のままです。画面を作り直す Phase で、`render/`(描画)と `ui/`(React の部品)に分ける予定です。
- `core/model/convert.ts` は、範囲の計算を引数で受け取っています(Phase 1a で core の外にあったため)。Phase 1c で同じ `core/` に移ったので、直接呼ぶ形に簡単にできます(処理を変えないため、今はそのまま)。
