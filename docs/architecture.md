# フォルダの役割と依存の向き

2D CAD Viewer を本格的な 2D CAD へ段階的に広げるための、フォルダの役割と規則です(Phase 1c で整理)。
規則は自動テスト `src/architecture.test.ts` で確認しています。違反すると `npm test` が失敗します。

## 全体の形

```
画面(React)  App.tsx / components/ / cad-view/
     │
     ▼
app/  アプリの動き(コマンドなど。画面の機能は使わない)
     │
     ▼
io/  ファイル形式の読み書き(DXF・DWG、ワーカーの中の処理)
     │
     ▼
core/  CADの中核(モデル・幾何・選択・スナップ・測定・表示の座標)
     │
     ▼
types/  共通の型(CadEntity など)
```

- **矢印の向き(上から下)にだけ、読み込んでよい**のが原則です。下の層は、上の層を知りません。
- **下の層へは、1つ飛ばしでも直接読み込んでよい**です。たとえば、画面から `core/` を直接使ってかまいません(`CadCanvas` は、選択やスナップを直接使っています)。

## 各フォルダの役割

| フォルダ | 役割 | 読み込んでよいもの | 使ってよい実行環境の機能 |
|---|---|---|---|
| `src/core/` | CAD の中核。画面にも、ファイル形式にも依存しない。 | `core/`、`types/` だけ。外部パッケージは使わない。 | ECMAScript の標準だけ(ブラウザの `window`・`document`・Canvas も、Node の機能も使わない) |
| `src/io/` | ファイル形式の読み書き。DXF・DWG の解析、元データの保持、**ワーカーの中で動く処理**。 | `io/`、`core/`、`types/`、決めたパッケージ(`dxf-parser`、`@mlightcad/libredwg-web`)。画面は読み込まない。 | ECMAScript の標準と、ワーカーで使える機能(`TextDecoder`、`WebAssembly`、`console` など)。DOM(画面)は使わない。 |
| `src/app/` | アプリの動き。コマンド(名前・別名・段階・依頼)など、画面と中核の間で「何をするか」を決める。React や画面の機能は使わない(だから単体テストできる)。 | `app/`、`core/`、`types/` だけ。外部パッケージは使わない。(`io/` は、保存とつなぐ段階で必要になったら、規則の変更として加える) | ECMAScript の標準だけ |
| `src/types/` | 共通の型。**型の宣言だけ**を置く(値・関数・クラスは置かない)。 | `types/` の型だけ(`import type`)。 | － |
| `src/cad-view/`、`src/components/`、`App.tsx`、`src/hooks/`、`src/utils/` | 画面(React と Canvas の描画)。**ワーカーを起動・管理するのも画面の側**(`App.tsx`)。 | すべて。ほかの層からは読み込まれない。 | すべて |

### 例外

- **DWG 変換の WASM:** `io/` は、`node_modules/@mlightcad/libredwg-web/wasm/` のフォルダだけを、相対パスで読み込んでよいです。パッケージが、このファイルを公開範囲(`exports`)に含めていないためです。`node_modules` のほかの場所を相対パスで読み込むことはできません。

### 規則の対象外(テスト用のもの)

次のものは、規則の検査の対象外です(何を読み込んでもよい)。その代わり、**本番のコードから、これらを読み込むことはできません。**

- テスト本体(`*.test.ts`、`*.test.tsx`)
- テスト用の補助(`testHelpers.ts`)
- 回帰テスト(`src/regression/`)、E2E(`e2e/`)

## 検査の方法

文字の検索ではなく、TypeScript 自身を使って検査します。そのため、コメント、文字列、変数名(`document` という名前のCADドキュメントなど)に惑わされません。

- **依存の向き:** 構文解析で、`import`、`export … from`、動的 `import()`、型の `import("…")`、`new URL("…", import.meta.url)` を取り出して調べます。読み込む先を文字列で直接書いていない動的 `import()` は、違反とします。
- **実行環境の機能:** `core/` と `types/` は「ECMAScript の標準の型だけ」で、`io/` は「ECMAScript とワーカーの型だけ」で、型チェックします。使ってはいけない機能(`window`、`document.createElement`、`localStorage`、Canvas など)を使うと、TypeScript が「見つからない」として検出します。

## `core/` の中身

| フォルダ | 内容 |
|---|---|
| `core/model/` | ドキュメントモデル(図形の一覧、ID、レイヤー)、描画用モデルとの変換 |
| `core/geometry/` | 幾何(距離、交点、行列、スプライン、ポリラインの膨らみ、楕円の変換、図形の頂点と線分) |
| `core/style/` | 線種(破線のパターン)、線の太さ |
| `core/spatial/` | 空間索引(図形の範囲、格子) |
| `core/selection/` | 選択(クリック、窓、交差) |
| `core/snap/` | スナップ(端点、中点、交点、最近点) |
| `core/measurement/` | 測定 |
| `core/view/` | 表示の拡大と位置(カメラ) |

| `core/commands/` | コマンドの登録簿、コマンドの進め方(段階)、実行の状態、座標入力の読み取り、入力の履歴(Phase 2) |

これから作るもの(予定): `core/history/`(Undo/Redo、Phase 3)。

## `io/` の中身

| フォルダ | 内容 |
|---|---|
| `io/dxf/` | DXF の解析(`DxfParserAdapter`)、文字コード、レイヤーの表、DWG→DXF の変換、ワーカーの中の処理、元データの索引と差分の適用(保存の土台) |

## `app/` の中身

| フォルダ | 内容 |
|---|---|
| `app/commands/` | アプリに最初から入っているコマンド(OPEN・CLOSE・FIT・MEASURE・FULLSCREEN・ID)。コマンドが返す「アプリへの依頼」(`AppRequest`)の型。依頼を実際に実行するのは画面の側(`App.tsx`)。 |

ツールバーのボタン、ショートカット(F・M)、コマンドライン、図面のクリックは、どれも `CommandSession` という1つの入口からコマンドを動かします。

## 新しいコードを置く場所の決め方

1. 画面に関係なく、CAD としての計算や状態の変更か → `core/`
2. ファイル形式(DXF、DWG、将来の独自形式・PDF)に関わるか → `io/`
3. 「どのコマンドが、何をするか」など、画面に関係しないアプリの動きか → `app/`
4. 画面の部品や、マウス・キーボードの扱い、ワーカーの起動か → 画面の側(今は `cad-view/`、`components/`、`App.tsx`)

迷ったら、下の層(`core/`)に置けないかを先に考えます。下の層に置いたほうが、テストしやすく、壊れにくくなります。

## 今後の方針: 編集の結果を保存へ渡す方法(Phase 2・3・保存の Phase で具体化)

編集(コマンド、Undo)は `core/` に、保存(元データへの差分の適用)は `io/` にあります。`core/` は `io/` を読み込めないので、次の形でつなぎます。

- `core/` は、**ファイル形式に依存しない「変更の内容」**(追加・削除・変更した図形のID と、変更前後の図形)を作って返す。Undo も、この変更の内容を記録する。
- `io/` は、その「変更の内容」を受け取り、図形のID から元データの記録を引いて、差分(削除・差し替え・追加)に変換して適用する。
- 両者を呼び出して結びつけるのは、画面の側(将来は、画面と中核の間に置く「アプリの層」)。

## まだ整理していないもの(後の Phase で行う)

- 画面の側(`cad-view/`、`components/`)は、今の場所のままです。画面を作り直す Phase で、`render/`(描画)と `ui/`(React の部品)に分ける予定です。
- `core/model/convert.ts` は、範囲の計算を引数で受け取っています(Phase 1a で core の外にあったため)。Phase 1c で同じ `core/` に移ったので、直接呼ぶ形に簡単にできます(処理を変えないため、今はそのまま)。
